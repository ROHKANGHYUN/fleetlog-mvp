## 기준선과 공간·데이터 분리

- 시작 시 Git 메타데이터가 없는 폴더의 `MANIFEST.sha256` **125개 소스**가 모두 일치했습니다. 기존 사용자 변경을 되돌리지 않았습니다.
- 시작 기준 DB는 `services/api/data/fleetlog.sqlite`입니다. `mode=ro`와 `PRAGMA query_only=ON`으로 운행4건·영수증6건을 읽고 전체 행을 기준으로 남겼습니다. 보고 숫자에 맞춰 데이터를 변경하지 않았습니다.
- 기존 API는 PID49059/4000, Vite는 PID49060/5173입니다. 시작부터 종료까지 유지했고 테스트 서버로 재사용하지 않았습니다.
- 시작 기준 여유 공간은 **1,681,776,640B**, 최종 DB 비교 당시 **1,714,900,992B**였습니다. 이전0.62GB 보고와 현재 관측을 구분합니다. SDK/이미지/새 브라우저/새 의존성·대용량 녹화·패키징을 다운로드하거나 생성하지 않았습니다. 사용자 파일·SDK·AVD·공유 캐시는 삭제하지 않았습니다.
- `startDemo()`는 `mkdtemp` 새 디렉터리의 `demo.sqlite`와 빈 loopback 포트만 사용합니다. HOST/PORT/FLEETLOG_DB_PATH가 개발 DB를 선택하지 않습니다. 사용 중인 지정 포트는 실패하고 기존 서버를 종료하거나 재사용하지 않습니다.
- 브라우저는 실제 설치 Chrome157.0.8103.52의 새 프로세스/독립 컨텍스트를 사용했습니다. 기존 개발 origin·사용자 Chrome 프로필·브라우저 저장소를 지우지 않았습니다. 일반 시크릿 창 여러 개가 같은 세션을 공유할 수 있으므로 운영 대본은 ‘새 독립 시크릿 세션 또는 별도 시연용 프로필’을 명시합니다.
- 시연 전체 초기화 API와 클라이언트 삭제 UI는 없습니다. 포트/주소만으로 소유권을 추정하지 않으며 처음부터는 새 서버·새 컨텍스트를 만듭니다. 기존 domain `resetLocal()` API는 호환성을 위해 남겼지만 앱 UI에 호출 경로가 없습니다.

## 실행한 시연

루트에서 `npm run demo`를 실제 실행했습니다. 출력된 주소는 이번 실행의 **http://127.0.0.1:61503**, DB는 이번 `chagok-demo-grLhhw` 임시 디렉터리였습니다. 이 주소는 이력이며 다음 시연의 고정 주소가 아닙니다.

## 테스트·증거·정리

최종 실행 명령은 `npm run check`와, 이미 빌드된 현재 웹에 대한 `npx playwright test`입니다. 표준 재현은 다음과 같습니다.

```sh
npm run demo                  # 터미널의 실제 주소를 새 독립 창에서 열기
# 종료 후 검증할 때
npm run check
npm run test:e2e              # 빌드 + 같은 Playwright 전체 테스트
# 전체 시연 두 회차만: npx playwright test e2e/rehearsal.spec.mjs
```

- 자동 테스트는 기존156개에 안전한 시연 재시작 안내/삭제 조작 부재 회귀1개를 추가해 **157개**입니다. 기존 테스트 삭제/조건 약화는 없습니다.
- 실제 브라우저는 기존16개에 연속 전체 시연2개를 추가해 **18개**입니다. mock 시간/결과와503만 제어했으며 전송 성공·ACK·SQLite·관리자는 실제 로컬 구현을 사용했습니다.
- 현재 소수 이미지 `test-results/step7/voice-draft.png`, `received-summary.png`는 가상 음성 초안과3건/70.2km 집계를 보여 줍니다. 두 장 합계 약136KB이며 직접 열어 가독성·MOCK 구분을 확인했습니다. CLI 탐색 진단 이미지 한 장을 포함해 이번 PNG는 총약188KB입니다. 녹화는 하지 않았습니다.
- 최종 로그: `test-results/step7/check-final.log`, `e2e-final.log`. 전체 Playwright JSON/기존 크기별 이미지 위치는 기존 설정대로 `test-results/step5/`입니다.
- 회차별 결과 JSON은 Playwright attachment와 `test-results/step7/rehearsal-1.json`, `rehearsal-2.json`에 있습니다. CLI 출력 주소/검증·종료 근거는 `cli-run.json`입니다. 모두 ignore 대상입니다.
- `before/database.json`과 `after/database.json`의 전체 trip/receipt 행이 일치합니다. 기존 네 운행의 server/local revision은2/2·1/1·2/2·1/1 그대로이며 receipt 본문·ACK·시각도 동일합니다.
- 마지막 기존 PID49059/49060 listener 및 웹/health200을 확인했습니다. CLI61503과 최종 반복61807/61818 listener는 종료됐습니다. fixture는 finally에서 자기 서버/DB만 정리했고 사용자 프로세스를 종료하지 않았습니다. 자료는 `after/processes.json`에 있습니다.

## 인수인계와 남은 제한

발표자는 웹의 로컬 저장·목적 보완·Outbox·실제 HTTP/SQLite 수신·재시도/ACK/중복 방지·Fleetlog 비즈를 시연할 수 있습니다. 차량 상태/거리와 음성 안내·인식 결과는 **MOCK**입니다. 운전자 인증·다중 회사 권한·관리자 승인·기간 마감·세무신고와 결과 수신은 후속 개발입니다. GPS 서비스 대비 정확도·우위·성과 수치나 세법상 적격성을 검증하지 않았습니다.

이전 Android 기본44개·SDK 옵션49개·두 APK 빌드/서명 결과는 [STEP6_RUNTIME.md](STEP6_RUNTIME.md)의 과거 결과입니다. 이번에 Android 도구 설치·APK 재빌드·실행을 반복하지 않았습니다. Android 화면, 실제 Pleos 서비스/누적거리/주행 제한/음성, 실차는 여전히 **미실행**입니다.

다음 조건은 명시적인 테스트 장치 또는 호환 Pleos AVD, 실제 설치/실행 예산을 만족하는 공간, 팀 프로젝트/서명/서비스 권한과 버전입니다. 환경 확보 후 SDK 로딩→초기화→서비스 연결→capability→최초 값→변경 이벤트→해제/재연결을 따로 검증하고 실제 원본 타입·단위·범위·freshness·주차/UX 제한과 변환을 대조해야 합니다. 공개 artifact나 APK 빌드를 실제 연결로 대체하지 않습니다. 최신 작업 시작 지점은 [CODEX_HANDOFF.md](CODEX_HANDOFF.md)입니다.
