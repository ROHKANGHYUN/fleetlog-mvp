# Fleetlog · 1단계 실행 가능한 개발 기준선

검증일: **2026-11-15 KST**. 실행 환경: macOS arm64, Node.js **24.11.1**, npm **11.6.2**, 로컬 Google Chrome.

**웹 개발 기준선은 확보했습니다.** 개발 서버 실행, 기존 테스트 45개, 웹 타입 검사·빌드, 실제 브라우저의 확정/미확정/보완 흐름과 서버 재시작을 확인했습니다. Android는 누락 소스를 복구하고 빌드를 시도했으나 디스크 공간 부족과 SDK 미설치가 남아 있어 APK 기준선은 아직 확보하지 못했습니다.

이 문서는 이전 패키지 작성 환경의 `listen EPERM`·브라우저 미검증 기록을 현재 PC의 실행 결과로 갱신합니다. 과거의 정적 검사와 이번 실제 실행 결과를 혼동하지 않습니다.

SQLite의 experimental 경고는 나타났으며 테스트 실패는 없었습니다. 기존 45개 자동 테스트는 주행 입력 차단, 명시적 저장, 미확정 전송, 재실행 gap, 늦은 ACK, 동일 본문 재시도, 선행 ACK 후 후행 버전 준비, 저장 실패, stale writer 거부, 종료 후보 시각, 원본 불변, 409 보류, SQLite 트랜잭션 및 API 입력 검사를 포함합니다.

기존 통합 테스트는 프로세스 내부 HTTP handler 호출입니다. **이번 실제 TCP·Chrome 조작 검증은 별도로 수행했으며, 자동 브라우저 E2E 테스트를 새로 구축한 것은 아닙니다.**

## 실제 브라우저 검증

Chrome에서 `http://127.0.0.1:5173`을 열고 실제 버튼·입력란을 조작했습니다. 기존 로컬 초기화 버튼은 사용하지 않았습니다. 최초 브라우저 저장 수와 서버 수신 수는 모두 0건이었고, 아래 mock 기록 3건을 검증 자료로 남겼습니다.

1. **명시적 시작**: 기록 시작 전 주행 전환에서는 저장 0건을 유지했고, 주차 후 시작하라는 안내가 표시됐습니다.
2. **확정 운행**: 기록 시작 → 주행 23.4km → 주차 → 운행 마치기 → 일반 업무/메모 입력 → 요약 → 확인하고 저장. 로컬 저장 1건/전송 대기 1건을 확인했습니다. 전송 전 회사 관리에는 0건이었고, 서버 전송 후 서버 수신 완료·대기 0건, 관리자 1건/23.4km가 됐습니다.
3. **미확정 보관**: 수집 세션을 유지한 채 다음 23.4km 운행을 만들고 오프라인 모의 상태에서 미확정으로 보관했습니다. 로컬 2건/대기 1건, 전송 버튼 비활성 상태를 확인했습니다. 온라인 전환 후 수동 전송하자 관리자 확인 필요 1건으로 표시됐습니다. 이는 앱의 오프라인 스위치 검증이며 실제 네트워크 단절 시험은 아닙니다.
4. **나중에 용도 보완**: 미확정 목록 → 용도 확인 → 출퇴근/메모 → 요약 → 저장. 전송 전 서버 목록 JSON은 기존 미확정 v1과 완전히 동일했습니다. 전송 후 **같은 tripId의 localRevision/serverVersion이 1→2**, 관리자 확인 필요 0건, 총 2건/46.8km를 확인했습니다. API 원본 비교에서 시작·종료 시각, 시작·종료 누적거리, 품질, 차량/이용자 ID가 모두 유지됐습니다.
5. **단일 writer**: 같은 origin을 두 번째 탭에서 열자 잠금 안내만 표시됐습니다. 첫 탭을 닫고 두 번째 탭을 다시 불러오자 기록 2건을 유지한 채 정상 시작됐습니다.
6. **주행·음성 제한과 재실행**: 세 번째 운행에서 모의 음성 대기 중 주행으로 전환하자 용도·메모·음성 입력이 사라졌습니다. 미완료 상태에서 새로고침하자 수집이 중단되고 저장 3건/미확정 1건이 됐습니다. 자동 수집 재개는 없었습니다.
7. **gap 원본 보존**: 복구된 세 번째 기록을 전송하고 용도를 일반 업무로 보완한 뒤 재전송했습니다. v2가 돼도 `quality: gap`과 원본 시각·거리는 그대로였으며 관리자 확인 필요 1건으로 남았습니다. 유효 거리 합계는 **46.8km**로 유지됐고, gap 거리는 합계에서 제외됐습니다.
8. **화면 확인**: 넓은 차량 화면, 앱 내부의 ‘좁게’ 미리보기, 관리자 목록·상세·용도별 요약을 확인했습니다. 보완 저장 안내 수정도 실제 화면에서 확인했습니다. 이는 실제 모바일 viewport·기기 전체의 반응형 검증은 아닙니다.
9. **서버 재시작**: 개발 서버를 종료하고 빌드본 서버를 실행한 뒤 기록 전체를 비교했습니다. 이후 개발 서버를 다시 띄우고 관리자에서 3건/확인 필요 1건/46.8km를 확인했습니다.

최종 서버 요약은 `receivedCount: 3`, `unconfirmedCount: 0`, `invalidDistanceCount: 1`, `readyForPurposeReview: false`입니다. 이는 mock 수신 상태이며 관리자 승인·마감·신고 결과가 아닙니다.

## 수정한 내용

- **누락된 Android 저장·전송 소스 복구**: `TripRepository.kt`, `DevSyncClient.kt`를 같은 모델/ViewModel을 가진 이전 로컬 스타터에서 내용 변경 없이 복구했습니다. 근거·해시는 [Android 검증 기록](../apps/car-android/VALIDATION.md)에 있습니다.
- **소스 제외 오류 수정**: `.gitignore`의 광범위한 `data/`를 `/services/api/data/`로 좁혔습니다. SQLite는 계속 제외하고 Android의 `.../demo/data/` 소스는 보존합니다. 소스용 `MANIFEST.sha256`도 복구 파일·검증 문서를 포함해 갱신했습니다.
- **의존성 패치**: Vite 7.3.6→7.3.8, 간접 의존성 source-map-js 1.2.1→1.2.2를 적용했습니다. package.json/잠금 파일에 반영하고 재설치·audit·전체 check로 확인했습니다. 확인한 원문: [Vite 릴리스](https://github.com/vitejs/vite/releases/tag/v7.3.8), [source-map-js 릴리스](https://github.com/7rulnik/source-map-js/releases/tag/v1.2.2), [Vite 관련 보안 공지](https://github.com/advisories/GHSA-587h-7wmj-h5pm), [source-map-js 보안 공지](https://github.com/advisories/GHSA-68fv-2mgg-jv7q).
- **보완본 전송 안내 수정**: 이미 v1이 수신된 기록의 v2 저장 후에도 ‘회사 화면에 나타나지 않는다’고 안내하던 문구를 수정했습니다. 이제 ‘이번 수정본은 아직 서버에 반영되지 않았고 회사 화면에는 이전 수신본이 표시된다’고 구분합니다.
- **mock 표시 강화**: 차량·관리자 공통 헤더에 `MOCK · LOCAL DEVELOPMENT`를 표시했습니다. 기존 가상 데이터·실차 미연결·모의 음성 안내도 유지했습니다.

도메인 상태 전이, eventId/ACK/리비전 계약, 원본 필드, 브라우저 Web Lock, mock/live 경계는 변경하지 않았습니다. 기존 데이터 삭제나 초기화, 실제 Pleos 연동, 외부 배포·전송은 수행하지 않았습니다.

## 실행하지 못했거나 제한된 검증

- **Android 테스트·APK**: JDK17은 설치되어 있었고 Gradle 8.10.2는 이번에 설치했습니다. 테스트/APK 명령은 `:classpath` 의존성 다운로드 중 `No space left on device`로 실패해 Kotlin 컴파일·JUnit에 도달하지 못했습니다. APK 없음. SDK35/build-tools35.0.0/adb/에뮬레이터/AVD도 미설치 상태입니다. 실패 직후 디스크 가용량은 100MiB대였습니다. [상세 결과와 재현 명령](../apps/car-android/VALIDATION.md)을 따릅니다.
- Android 런타임 저장·재실행·직렬화·HTTP 동기화, 차량 에뮬레이터 검증은 미실행입니다. 복구 소스 정적 확인을 실제 빌드·실행 성공으로 취급하지 않습니다.
- 브라우저 자동화 회귀 테스트, 실제 네트워크 단절/ACK 응답 유실/409 충돌의 브라우저 주입 시험은 미실행입니다. 관련 도메인·API 자동 테스트는 통과했습니다.
- 실제 모바일 viewport, 여러 브라우저, 실차 화면 크기·입력장치 검증은 미실행입니다. 개발 소스 수정 시 Vite의 자동 페이지 새로고침은 확인했으나 UI 상태를 보존하는 HMR을 검증한 것은 아닙니다.
- 실제 Pleos SDK·차량 신호·음성·운전자 인증·운영 배포는 미구현이며 API·단위·권한을 추정해 추가하지 않았습니다.
