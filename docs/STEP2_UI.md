작업일: **2026-11-15 KST**. 대상은 React 웹 차량 시뮬레이터입니다. Android 차량 앱은 별도 클라이언트이며 이번 단계에서 Android 코드·실제 Pleos SDK를 변경하지 않았습니다.

## 디자인과 조작 기준

- 서비스는 **Fleetlog**, 관리자 작업공간은 **Fleetlog 비즈**, 소개는 **“말 한마디로, 운행 기록은 Fleetlog.”**입니다.
- 차량 영역은 네이비 `#10232f`, 주요 행동은 청록 `#5ce0cf`입니다. 바깥 개발 작업공간과 영역·대비를 분리했습니다.
- 차량의 주요 버튼은 64px, 보조 버튼·입력란은 56px 이상을 목표로 설계했습니다. 이는 이번 **웹 프로토타입의 디자인 목표**이며 공식 차량 UX 인증 기준이 아닙니다.
- 각 화면의 다음 행동을 청록색으로 강조하고, 목록 이동·음성·세션 종료는 보조 위계로 낮췄습니다. 목록의 용도 확인은 해당 기록에 연결됩니다.
- 1000px 초과 창에서는 개발 제어를 옆에 배치하고, 좁은 창에서는 차량 영역 아래로 내립니다. ‘좁게’ 미리보기는 최대 440px입니다. 높이를 고정해 콘텐츠를 자르지 않고 필요한 경우 세로 스크롤합니다.
- 주행/주차, 통신 모의, 음성 결과, 창 폭, 로컬 초기화는 개발 제어에만 있습니다. 차량 영역에는 내부 eventId/serverVersion을 표시하지 않습니다.
- 모든 차량 화면에 MOCK 표시를 유지합니다. 음성은 실제 마이크·STT가 아닌 모의 응답입니다. 과도한 애니메이션은 사용하지 않았습니다.

## 화면별 행동과 도메인 연결

| 화면 | 실제 상태 | 주요 행동 / 연결 |
|---|---|---|
| 시작 전 | `screen=ready`, `active=false`, 주차 모의 | `start()`로만 수집 시작. 모의 이용자·차량 표시, `showPending()`으로 보완 목록 |
| 주행 중 | `driving=true`가 다른 화면보다 우선 | `active`에 따라 기록 중/미시작 구분. 차량 안의 버튼·목적·메모·음성·세션 종료 없음 |
| 주차 후 확인 | `screen=collecting`, `driving=false` | 양수 거리 관측 구간이 있으면 `finish()`. 주차 전환만으로 저장하지 않음 |
| 용도 입력 | `screen=purpose`, controller의 `draft` | `setPurpose()` → `review()`, 또는 `defer()`. 모의 음성도 `setPurpose()`로 초안만 반영 |
| 저장 전 확인 | `screen=review` | `save()`가 성공한 경우에만 controller가 saved로 전환. 수정은 `setPurpose()`로 purpose 복귀, 종료 후보 재생성 없음 |
| 저장 완료 | `screen=saved`, `lastSavedTripId` | 로컬 저장 완료 우선. ACK·Outbox에서 별도로 전송 상태 표시. `home()` 또는 `showPending()` |
| 미확정 목록·보완 | `screen=pending`, `purpose=null` 기록 | `editTrip(tripId)`로 기존 기록 보완. 현재 운행 미완료와 버전 충돌을 별도로 안내·차단 |
| 세션 종료 확인 | 주차 중인 controller 상태 + 확인창 표시만 UI 상태 | `stop()` 호출. 미완료 양수 거리 구간 미확정 보관, 수집 중지. 재개는 다시 `start()` |

별도 가짜 운행 상태로 화면을 전환하지 않습니다. 탭, 창 폭, 확인창, 모의 음성 진행·안내는 UI 상태이고, 수집·운행·초안·저장·전송은 기존 controller만 변경합니다.

### 보존한 상태 경계

- 입력 중 주행 전환은 controller가 초안·보완 대상·종료 후보를 취소하며, UI도 음성 타이머/결과와 확인창을 취소합니다.
- `distanceKm()`는 gap, 누락·역전 거리를 ‘거리 확인 필요’로 표시합니다. 저장 전 요약은 후보 종료 거리를 우선 사용합니다.
- 저장 실패는 예외로 처리하고 기존 purpose/review 화면을 유지합니다. 실패 알림을 차량 영역 안에 표시하며 성공 화면으로 바꾸지 않습니다.
- `ackedLocalRevision >= localRevision`인 기록에만 서버 수신 완료를 표시합니다. 이전 ACK가 있는 보완본은 대기 상태이며 Fleetlog 비즈에는 이전 수신본이 남는다고 안내합니다.
- 기록별 실패/충돌은 최신 이벤트만이 아니라 해당 운행의 **전체 Outbox**에서 확인합니다. 선행 변경 실패·충돌에 막힌 후행 변경을 놓치지 않습니다.
- `sync()`는 실패 기록을 남기고 resolve할 수도 있으므로 Promise 반환만으로 성공을 안내하지 않습니다. 실제 잔여 Outbox와 ACK 상태를 확인합니다.
- 전체 큐의 `syncing`은 전체 전송 버튼에만 표시합니다. 아직 요청하지 않은 개별 기록을 ‘자신의 수신 응답 대기’라고 표시하지 않습니다.
- Outbox 본문·동일 eventId 재시도·선행 ACK 후 후행 버전 준비·409 보류·원본 불변 규칙과 Web Lock 구현은 변경하지 않았습니다.

## 실행한 검증

### 자동 테스트와 빌드

`npm run check` 실행 결과 **57/57 통과**, 실패·skip 0입니다. 기존 45개에 의미 있는 회귀 테스트 12개를 추가했습니다. 스타일 값 자체를 그대로 비교하는 테스트는 추가하지 않았습니다.

- 도메인 회귀 2개: 요약→수정→재확인 후 원래 종료 시각/거리 유지, 보완 초안 작성 중 재출발해도 기존 저장 기록과 Outbox 보존.
- 전송 표시 5개: 오프라인 대기/실제 ACK 구분, 선행 실패·충돌 반영, 잘못된 ACK 차단, 전역 전송 중에도 미요청 기록은 대기 유지.
- 실제 App 서버 렌더링 5개: 실제 controller 화면 연결, 주행 중 모든 차량 조작 제거, 저장 실패 후 review 유지, 전송 실패/ACK 구분, 빈 목록/미완료/충돌 안내 구분, gap 보완 후 거리 불명확 표시. 일부 테스트가 여러 상태를 묶어 검증합니다.
- TypeScript와 Vite 7.3.8 웹 빌드 통과. QA TSX도 타입 검사에 포함되며, QA 페이지는 기본 `dist` 번들에 포함되지 않습니다.

서버 렌더링 테스트는 실제 React App의 출력과 controller를 연결한 검사이며 DOM 클릭·포커스·브라우저 레이아웃 검사를 대체하지 않습니다.

### 실제 Chrome / 실제 로컬 API

1. 기존 브라우저 기록 3건을 유지한 채 기록 시작 → 모의 주행 23.4km → 주차 → 운행 마치기 → 개인 용도·메모 → 요약 → 저장을 실제 조작했습니다.
2. 저장 직후 ‘이 기기에 저장했습니다’와 ‘전송 대기’를 확인했습니다. 서버 전송 후 실제 ACK로 ‘서버 수신 완료’가 됐습니다.
3. 기록 세션 종료 확인 → 종료 후 시작 전 화면 → 다시 주행 전환을 실행했습니다. 다시 시작하지 않았으므로 ‘주행 중 · 수집 중지’이며 운행은 추가 생성되지 않았습니다.
4. Fleetlog 비즈에서 기존 3건 + 새 검증 기록 1건 = **4건**, 유효 거리 **70.2km**, gap 확인 필요 **1건**을 확인했습니다.
5. HTTP 재조회로 기존 3건의 전체 수신 JSON이 작업 전과 동일한지 비교했습니다. 이번에 추가된 기록은 메모 `2단계 차량 화면 검증 · mock`, 용도 `personal`, 서버 버전 1입니다. 초기화는 수행하지 않았습니다.
6. 네이비 차량 영역·청록 주요 행동·개발 제어 옆 배치·시작 화면을 Chrome 스크린샷으로 시각 확인했습니다.

## 확인하지 못한 항목과 남은 문제

- 브라우저 제어 도구가 QA 진행 중 연결을 잃었습니다. 앱 상태 재조회/재연결은 반복해서 **`js execution timed out; kernel reset`**으로 실패했고 브라우저 접근 호스트도 unavailable이었습니다. 실제 앱 오류로 단정하지 않았습니다.
- 따라서 2단계 UI에서 미확정→보완 저장, 음성 성공/실패 및 입력 중 재출발, 오프라인 저장→온라인 전송, 저장 실패/전송 실패/버전 충돌 알림의 **실제 클릭 검증은 완료하지 못했습니다**. 관련 controller·표시 회귀 테스트는 통과했으며 위 QA에서 재현할 수 있습니다. 1단계 브라우저 결과를 새 UI의 클릭 검증으로 대체하지 않았습니다.
- purpose/review/saved/voice/충돌 목록/세션 종료 확인의 세 viewport 전체 측정, ‘좁게’ 440px 모드, 실제 작은 Chrome 창의 스크롤·포커스·긴 메모 육안 검수는 남아 있습니다. 높이는 자동 확장과 세로 스크롤을 사용하며, 모든 조작이 540px 높이 한 화면에 들어간다고 보장하지 않습니다.
- 브라우저 테스트 결과 다운로드 버튼은 구현했지만 연결 중단으로 이번 결과 JSON 다운로드는 실행하지 못했습니다. 확인한 측정값은 위 표에 기록했습니다.
- 서버 버전 충돌 해소 UI는 기존처럼 미구현입니다. 자동 덮어쓰기나 새 eventId로 우회하지 않습니다.
- Android 빌드·실차 화면·실제 SDK·실제 음성·공식 차량 UX 적합성 검증은 이번 단계 범위 밖입니다.

## 다시 실행·검증하는 방법

```sh
npm ci
npm run dev
```

- 본 앱: `http://127.0.0.1:5173`
- 데이터가 격리된 QA: `http://127.0.0.1:5173/qa/`
- 전체 회귀/빌드: `npm run check`

QA에서 실제 앱 버튼으로 운행을 만든 뒤, 저장 전 확인 상태에서 상단 ‘저장 실패 모의 켜기’를 누르고 ‘확인하고 저장’을 누릅니다. 실패 안내와 review 유지·저장 수 미증가를 확인한 뒤 오류 모의를 끄고 다시 저장합니다. ‘전송 실패 모의 켜기’ 후 서버 전송을 눌러 실패 표시를 확인하고, 오류 모의를 끈 뒤 재전송해 ACK 완료를 확인합니다. 미확정 기록을 만든 뒤 ‘버전 충돌 모의 켜기’와 전송으로 보완 차단 안내를 확인할 수 있습니다. QA 새로고침은 QA 메모리만 새로 시작하며 본 앱 데이터에는 영향이 없습니다.

화면별로 ‘세 크기 모두 측정’을 실행하고, 각 크기에서 스크롤하며 육안 확인을 병행합니다. ‘검증 결과 저장’은 관측값과 크기별 측정값을 JSON으로 내려받습니다. QA는 개발 서버에서만 사용하며 Vite 기본 배포 번들에는 넣지 않습니다.

이번 실행 로그와 변경 전 소스/서버 비교본은 ignore 대상인 `test-results/step2/`에 있습니다. 소스용 `MANIFEST.sha256`는 변경 파일과 테스트/QA/문서를 반영하되 node_modules·dist·SQLite·검증 데이터는 제외합니다.
