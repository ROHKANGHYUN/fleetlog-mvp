# Fleetlog MVP 최종 인수인계

검증일: **2026-11-15 KST**. 현재 서비스 이름은 **Fleetlog**, 관리자는 **Fleetlog 비즈**입니다. 이전 요청에 적힌 서비스 이름보다 최근 이름 변경을 유지했습니다. 이 문서가 최종 구현·실행 결과의 기준이며 단계별 문서의 수치는 당시 이력입니다.

## 최종 구현 범위

```text
QR 또는 연결 코드 → 가상 직원·차량 연결
  → 모의 출발(차량 비움) → 모의 도착(주차 관측만)
  → 운행 마치기(종료 후보 고정) → 모의 음성 확인 또는 미확정 보관
  → 자동 저장·실제 로컬 HTTP 수신
  → 모바일에서 본인 미확정 목적 보완 → 관리자 자동 반영
  → 회사 전체 월별 집계 → 버전별 자료 생성·실제 CSV 다운로드
  → 서버 준비 조건 검사 → 모의 접수 중 → DEMO 접수 완료/모의 실패
```

화면 간 상태 공유, QR 발급·검증, HTTP, SQLite 저장, 다운로드는 실제입니다. 직원·차량 신호·거리·발화·비용·접수 결과는 가상/모의 데이터입니다. 실제 인증·회사 권한·STT·Pleos·Android/실차 실행·카드/회계·홈택스·실제 신고/납부·운영 배포는 포함하지 않습니다.

첨부 디자인의 차량 화면, 10분 QR/코드 공동 소비, 주차/주행/불명확 상태, 음성 시점, 원본·ACK·업로드 규칙을 재사용했습니다. 별도 운행 엔진을 추가하지 않았습니다. 차량·음성·uploader 원래 파일과 기존 36개 E2E는 이번 작업에서 변경하지 않았습니다.

## 설치·실행·전체 시연

필요 환경: Node **24.x**, npm, 웹 브라우저. 처음 받은 소스는 프로젝트 루트에서 설치하고 실행합니다. 이미 설치돼 있으면 `npm ci`는 생략합니다.

```sh
npm ci
npm run demo:mvp
```

실행 결과의 실제 주소를 새 시크릿 창/독립 브라우저 환경에서 엽니다. 고정 포트를 가정하지 않습니다. 시연 패널 `/mvp/control`의 링크로 차량 `/mvp/car`, 모바일 `/mvp/driver`, 관리자 `/mvp/admin`를 여세요. 패널은 자동 전송을 담당하므로 열어 둡니다.

| 순서 | 조작 | 정상 결과 |
|---|---|---|
| 1 | QR 링크 또는 모바일의 연결 코드 입력, 데모 직원 선택→차량 확인→이 차량에 연결 | 같은 서버 연결이 세 화면에 반영. 출발 시각/거리 없는 주차 대기 |
| 2 | 패널 모의 출발→모의 도착 | 주행 중 빈 차량, 도착 후 23.4km 모의 관측 카드. 아직 이벤트/수신 없음 |
| 3 | 차량 운행 마치기→패널 모의 나중에 | 후보가 고정된 미확정 기록 저장·자동 HTTP 전송 |
| 4 | 관리자/모바일 수신 완료 확인 | 실제 서버 수신 목록에 한 건, 용도 확인 필요 |
| 5 | 모바일 용도 보완→일반 업무/출퇴근/개인 선택, 목적지·상세 목적→보완 내용 확인→확인하고 보완 저장 | 보완 버전1, 관리자 자동 갱신, 운행 ID·원본·최초 ACK 유지 |
| 6 | 관리자 월별 자료에서 해당 시작 월 선택 | 한국 시작 날짜 기준 회사 전체·전체 차량 집계. 위 목록 필터와 독립 |
| 7 | 월별 자료 생성→운행 내역 CSV·가상 차량 비용 CSV | 같은 자료 ID/버전의 실제 파일 다운로드. 버전·생성 시각·가상 표시 |
| 8 | 준비 조건 충족 후 모의 제출 | 모의 접수 중→모의 접수 완료·DEMO 번호. 새로고침 후 유지 |

목적을 음성으로 확인하려면 3번에서 질문 안내 완료→모의 발화 전달→재확인 안내 완료→모의 네를 사용합니다. 브라우저 TTS가 차단되면 텍스트 확인 후 **안내 완료 모의**로 진행합니다. TTS 호출/완료 이벤트를 실제 청취나 인식 성공으로 설명하지 않습니다.

반복 시연은 해당 터미널 **Ctrl+C** 후 같은 명령으로 새 임시 DB·포트를 시작하면 됩니다. 초기화 API는 없습니다. 정상 종료는 이번 listener와 직접 만든 폴더만 정리하며, 강제 종료/SIGKILL의 정리는 보장하지 않습니다. 서버가 살아 있는 동안 새로고침은 연결·기록·자료·접수 결과를 다시 조회합니다. 기록 종료 상태는 새로고침으로 재개하지 않습니다.

기본 `127.0.0.1` QR은 PC용입니다. 휴대폰용 사설 IP 바인딩/QR 기준 주소의 명시적 설정은 [QR 접속 안내](MVP_STEP1_QR.md#pc와-휴대폰-접속의-차이)를 따릅니다. 실제 휴대폰·LAN은 미검증이며 자동 터널/외부 배포를 하지 않습니다.

### 추가 오류·복구 시연

- **업로드 차단:** 패널 운행 업로드 차단→두 번째 미확정 운행 저장. 차량 대기1건, 관리자 수신은 이전1건을 유지합니다. 패널 새로고침 뒤 업로드 복구→같은 eventId로 수신 총2건, 중복0건입니다. 차단은 운행 수신만 막고 QR·조회·제어 통신은 유지합니다.
- **자료 갱신:** 첫 자료 생성 후 같은 월 기록 추가/보완→옛 자료 갱신 필요. 옛 CSV·접수 번호는 유지됩니다. 새 자료 생성 또는 패널 월말 처리 재현→새 버전입니다.
- **모의 실패:** 패널 모의 제출 실패 재현→새 준비 완료 자료 제출→모의 실패. 모의 제출 성공으로 복구→관리자 모의 제출 재시도→같은 자료/접수의 시도2를 기록하고 완료합니다. 실제 외부 세무 서비스는 호출하지 않습니다.

## 보완·원본·수신 보존

`mvp_received_trips`·`mvp_trips`의 원본, `mvp_uploads.body`의 준비된 문자열, `mvp_trip_receipts`의 최초 ACK를 수정하지 않습니다. `mvp_amendments`와 요청 멱등 기록을 한 트랜잭션으로 저장하고 최신 화면에 purpose/destination/detailedPurpose/purposeConfirmed만 겹쳐 표시합니다.

- 서버가 원래 직원·회사·운행을 대조합니다. 현재 연결 해제 후에도 원래 직원은 보완할 수 있고 다른 직원은403입니다. 현재 본인 연결 차량이 주행/UNKNOWN이면 새 편집을 차단합니다.
- 미확정 수신 기록만 보완합니다. 확인된 기록의 일반 편집·관리자 강제 수정·원본 거리 정정은 없습니다.
- `expectedAmendmentVersion`이 맞지 않으면409입니다. 자동 병합/강제 덮어쓰기를 하지 않습니다. 같은 requestId+본문 재시도는 이력을 늘리지 않으며 다른 본문은409입니다.
- 수정자·시각·변경 전후·보완 버전을 기록합니다. 원본 시각·거리·품질·모든 귀속 ID는 그대로입니다. gap/incomplete는 목적 보완으로 정상화되지 않습니다.
- 최초 ACK의 `serverVersion:1`과 보완 `amendmentVersion:1`은 다른 버전입니다. 이전 운행 이벤트를 그대로 재전송하면 같은 ACK를 반환하고 보완 표시값은 되돌리지 않습니다.
- 저장 실패는 rollback하며 입력을 유지합니다. 직접 고친 본문이 같으면 같은 요청 ID를 재사용합니다. 계정 전환은 편집기를 unmount/abort/세대 검사하여 늦은 응답이 새 직원 화면에 적용되지 않습니다. 서버에서 이미 commit된 작업을 클라이언트 취소로 되돌렸다고 주장하지 않습니다.

## 관리자·월별 범위와 가상 비용

운행 목록은 **최신 수신본·시작 시각 내림차순**이며 한국 시작 날짜의 기간·직원·차량·용도를 필터합니다. 목록 요약과 수신 확인 필요 목록에 같은 필터를 적용합니다. 같은 운행의 미확정/거리 사유는 한 건으로 표시하고 사유별 건수는 겹칠 수 있습니다. 업로드 대기·문제는 회사 전체의 별도 목록이며 수신 운행에 섞지 않습니다. 상세는 원본과 보완 이력을 구분합니다. 조회 실패는 이전 값/실패 안내이며 빈 목록 성공으로 바꾸지 않습니다.

월별 자료는 **회사 전체·선택 월·전체 차량**, 운행 `startedAt`의 **Asia/Seoul(UTC+9)** 날짜 기준입니다. 예를 들어 `2026-10-31T14:59:59.999Z`는10월, `15:00:00Z`는11월입니다. 자정을 넘는 운행을 나누거나 거리를 재계산하지 않습니다. 목록 검색 필터를 월별 API/보고서 범위에 넘기지 않습니다.

수신 건수, 직원별/차량별/용도별 건수·유효 거리, 미확정·불완전·알려진 미전송을 구분합니다. 미확정은 업무용이 아닙니다. 불완전 거리의 합산 제외 건수를 표시하고 값은 null로 유지합니다. 데이터 없음과 실제 유효 거리0을 구분합니다. 알려진 미전송은 이 서버가 아는 종료 후 큐이며, 다른 장치나 기간 전체 누락을 탐지한 결과가 아닙니다.

| 고정 발생일 | 가상 차량 | 항목 | 금액(KRW) |
|---|---|---|---:|
| 2026-11-02 | 차량1 | 유류비 | 68,000 |
| 2026-11-04 | 차량1 | 주차비 | 8,000 |
| 2026-11-06 | 차량2 | 통행료 | 4,200 |
| 2026-10-20 | 차량2 | 유류비 | 55,000 |

출처는 모두 `dummy-fixture`이며 실제 결제/카드/비용 영수증이 아닙니다. 11월 합계80,200원, 10월55,000원이며 다른 월에는 복제하지 않습니다. 운행 ACK를 비용 영수증으로 쓰지 않습니다. 비용 CRUD·OCR·세율·공제·납부세액 계산은 없습니다.

## 스냅샷·CSV·모의 접수

보고서는 생성 당시의 운행 ID·보완 버전·원본/최신 목적·비용·집계·사유·회사/직원/차량 표시값을 고정 저장합니다. 이후 해당 월 수신·보완·미전송·참조 표시값이 바뀌면 fingerprint 비교로 갱신 필요입니다. 새 생성은 새 버전이며 기존 자료를 덮어쓰지 않습니다. 같은 생성 requestId 재시도는 같은 ID/버전/내용과 최신 갱신 필요 상태를 반환합니다.

화면의 선택 자료와 다운로드가 같은 `report.data`를 씁니다. CSV는 UTF-8 BOM·CRLF·인용/이스케이프로 한글·쉼표·따옴표·줄바꿈을 처리합니다. 선행 공백/제어문자 뒤 `= + - @` 수식도 작은따옴표로 보호합니다. 파일명은 `Fleetlog-DEMO-YYYY-MM-vN-trips.csv` / `costs.csv`이며 내용도 가상·실제 신고 아님을 표시합니다.

모의 제출은 서버가 **수신0건·용도 미확정·거리 불완전·알려진 미전송·갱신 필요**를 다시 검사해 차단합니다. 차단된 초안도 조회·다운로드는 가능합니다. 법적 세무 적격성 판정이 아닙니다.

`mvp_submissions`에 자료별 접수와 각 시도를 저장합니다. 제출 시 모의 결과·1초 뒤 처리 시각을 서버에 고정하고, 이후 월별/자료 조회에서 서버 시각이 도달하면 결과/DEMO 번호를 SQLite에 반영합니다. 프런트엔드 타이머로 성공을 만들지 않으며 실제 예약 작업도 아닙니다. 제출 requestId 재시도·처리 중/완료의 중복 제출은 접수를 늘리지 않습니다. 실패 후 새 요청은 같은 접수의 새 시도이고, 새 제출도 현재 준비 조건을 재검사합니다. 제출 후 월 데이터가 바뀌어도 당시 결과는 보존하고 새 자료 필요 상태를 별도로 표시합니다.

새 테이블은 MVP DB의 `mvp_amendments`, `mvp_reporting_requests`, `mvp_costs`, `mvp_reports`, `mvp_submissions`, `mvp_reporting_settings`입니다. 기존 개발 `/api/trip-events`·계약·스키마·DB는 변경하지 않았습니다. API 상세는 [API 문서](API.md), 경계는 [아키텍처](ARCHITECTURE.md)를 참고하세요.

## 기존 데이터·서버 보존과 알려진 이력

시작 시 소스 manifest153개는 일치했고 기존 변경을 되돌리지 않았습니다. 실제 개발 DB `services/api/data/fleetlog.sqlite`를 `mode=ro`·`PRAGMA query_only=ON`으로 열어 운행4건·수신 영수증6건의 모든 열을 기준으로 남겼습니다. 과거 건수에 맞춘 것이 아닙니다. 작업 후 같은 읽기 전용 절차로 전체 행을 다시 비교하여 **ID·버전·payload·ACK·원본/보완 값·모든 저장 시각이 동일**함을 확인했습니다. 건수만 비교한 것이 아닙니다. 근거는 `test-results/mvp-step3/before/database.json`, `after/database.json`, `preservation.json`입니다.

기존 API PID49059/4000·Vite PID49060/5173을 종료/재시작하지 않았고, 마지막에 같은 PID와 두 서버 HTTP200을 확인했습니다. 이번 CLI PID43648/50826만 SIGINT로 종료했으며 종료 코드0·포트 닫힘·자기 임시 폴더 삭제를 확인했습니다. 기존 브라우저/Android 저장소를 열어 초기화하지 않았습니다. package/lock·실행 명령·스크립트·기존 domain/API/Android와 차량 화면/음성/Outbox를 보존했습니다. 테스트와 CLI는 별도 임시 DB·포트·브라우저만 사용합니다.

과거 최초 QR 연결 실패1회는 **원인 미확정·미재현 이력**입니다. 이번 신규7개·전체43개·CLI에서는 재발하지 않았습니다. 실제 POST 상태/본문·선택 계정·서버 연결 진단을 유지했고 타임아웃 증가·자동 retry로 숨기지 않았습니다. 원인이 해결됐다고 단정하지 않습니다.

## GitHub 공유 준비

정확한 작업 루트는 프로젝트 폴더 `fleetlog-starter`입니다. 프로젝트와 상위 경로에 Git 작업 트리가 없어 `.git`·추적 파일·Git 이력이 없습니다(`git rev-parse` exit128). 상위의 다른 저장소를 작업 대상으로 삼지 않았습니다. Git이 없으므로 `git check-ignore`로 인덱스/이력을 검사했다고 주장하지 않으며, ignore를 적용하는 `rg --files --hidden --no-require-git` 후보 목록과 경로/내용 검토로 준비했습니다.
