# Fleetlog · 공모전 웹 시연 대본과 운영 절차

작성일: 2026-11-15 KST. 핵심 메시지는 **“차량에서 남긴 짧은 기록을 회사의 관리 업무까지 연결합니다.”**입니다. 아래는 **약 3분의 내부 연습용** 순서이며 공모전의 공식 발표 제한 시간이 아닙니다. 실제 음성·실차 시연이 아닌 **웹 MOCK 시연**으로 소개합니다.

이번 실행·반복·오류 복구·데이터 보존 결과는 [STEP7_DEMO_RESULT.md](STEP7_DEMO_RESULT.md)에 기록합니다. 직전 Android/JVM/APK 결과는 [STEP6_RUNTIME.md](STEP6_RUNTIME.md)의 과거 검증이며 이번 웹 시연 성공으로 Android 실행 범위를 넓히지 않습니다.

## 시작 전 준비

1. Node.js24와 설치된 프로젝트 의존성을 확인합니다. 루트에서 `node --version`, `npm run doctor`를 실행합니다. 최초 설치만 `npm ci`가 필요합니다. 이미 설치됐다면 다시 다운로드하지 않습니다.
2. `df -h .`로 여유 공간을 확인합니다. 이번 시연에는 Android SDK·시스템 이미지·새 브라우저 다운로드·대용량 녹화가 필요하지 않습니다.
3. 기존 개발 서버와 DB를 그대로 둡니다. 시연을 위해 4000/5173 서버를 종료하거나 SQLite·브라우저 저장소를 지우지 않습니다.
4. 화면은 1280×720 이상 가로 화면·브라우저 배율100%를 권장합니다. 좁은 화면에서도 동작하지만 관리자 필터/상세를 보려면 세로 스크롤이 늘어납니다. 이 크기는 웹 시연 준비 기준입니다.
5. 같은 작성 컨텍스트에는 탭 하나만 사용합니다. 차량 화면과 Fleetlog 비즈는 스크롤 중에도 보이는 상단 탭으로 전환합니다. 전환하면 화면 맨 위로 돌아갑니다. 두 번째 작성 탭은 Web Lock으로 차단될 수 있습니다.

프로젝트 루트에서 다음을 실행합니다.

```sh
npm run demo
```

터미널에서 **실제로 출력된 주소**를 복사합니다.

```text
Fleetlog WEB MOCK 데모: http://127.0.0.1:실제출력포트
새 임시 DB: 이번실행의임시폴더
```

`실제출력포트`는 설명용 자리표시자입니다. 주소나 포트를 추정하지 않습니다. 명령은 웹 빌드 후 **새 임시 SQLite·빈 로컬 포트·127.0.0.1 listener**를 만듭니다. 기존 `HOST`, `PORT`, `FLEETLOG_DB_PATH`로 개발 DB를 선택하지 않으며 사용 중인 서버를 재사용하지 않습니다. 기존 `NODE_ENV=production` 거부와 외부 바인딩 제한도 유지합니다.

포트를 직접 정해야 할 때만 `npm run demo -- --port=4307`처럼 지정합니다. 이 숫자는 예시이며 사용 중이면 시작에 실패합니다. 해당 프로세스를 종료하지 말고 다른 빈 포트를 사용합니다.

### 독립 브라우저와 시작 확인

출력 주소는 **시연 전용의 새 시크릿 세션 또는 별도 시연용 브라우저 프로필**에서 엽니다. 개발 환경에서 사용하던 창/프로필을 재사용하지 않습니다. 다른 시크릿 창이 이미 열려 있어 독립 저장소인지 확실하지 않다면 별도 시연용 프로필을 선택합니다. 다른 사용자 창을 임의로 닫거나 그 저장소를 지우지 않습니다. 자동 검증은 Playwright의 새 `browser.newContext()`로 저장소를 확실히 분리합니다.

처음에는 차량의 **저장 0건·미전송 0건**, Fleetlog 비즈의 **아직 서버가 수신한 운행이 없습니다**를 확인합니다. 예상 밖 기록이 보이면 초기화하지 말고 실제 출력 주소·브라우저 환경부터 확인한 뒤 새 격리 환경에서 시작합니다.

준비할 데이터는 화면의 **샘플 이용자·샘플 법인차량**, 관리자 ID `demo-driver-001`·`demo-car-001`뿐입니다. 이름·번호판·거래처명·메모에 실제 개인정보를 넣지 않습니다. 모의 인식 문장은 **“일반 업무, 가상 거래처 미팅”**, 메모는 아래의 `가상 시연` 문구를 사용합니다.

### 처음부터 다시 하기와 종료

**시연 전용 전체 초기화 API는 없습니다.** 소유권을 확인할 수 없는 현재 origin의 저장소를 지우지 않도록 개발용 제어의 로컬 초기화 버튼도 제공하지 않습니다. 처음부터 연습하려면 이번 데모 터미널에서 Ctrl+C로 종료하고 `npm run demo`를 다시 실행한 뒤 새 독립 브라우저 컨텍스트로 엽니다. 새 DB와 빈 브라우저 저장소를 함께 사용해야 건수가 어긋나지 않습니다. 기존 개발 데이터·저장소를 삭제하는 방식으로 반복하지 않습니다.

Ctrl+C/SIGTERM은 이번 스크립트가 만든 listener와 출력한 임시 DB 폴더만 정리합니다. 서버 종료가 브라우저 기록까지 삭제하는 것은 아닙니다. 기록 증거가 필요하면 종료 전에 가상 데이터 화면/결과만 남깁니다. 강제 종료·전원 차단 후의 임시 폴더 자동 정리는 보장하지 않으므로 다른 임시 폴더를 일괄 삭제하지 않습니다.

## 오류 복구 연습과 현장 대응

복구 연습은 약30~60초를 추가합니다. 자동 브라우저 검증에서는 HTTP503을 한 번 주입해 실제 화면의 실패 안내·기록 보존·같은 이벤트 재시도를 확인합니다. 발표자가 장애를 재현하려고 기존 서버를 종료하거나 로컬 데이터를 삭제하지 않습니다. 화면에서 쉽게 설명할 때는 **오프라인 모의→로컬 보관→온라인→명시적 전송**을 사용합니다.

| 상황 | 기록을 보존하는 조치 |
|---|---|
| 전송 대기·일시 실패 | 저장 건수/미전송 건수와 안내를 확인합니다. 연결 복구 뒤 **서버 전송 다시 시도**를 누르고 ACK를 기다립니다. 기록을 다시 만들거나 ID를 바꾸지 않습니다. |
| 서버 수신 완료가 늦음 | 성공을 먼저 말하지 않습니다. 수신 확인 중·실패·대기를 구분하고 Fleetlog 비즈의 실제 최신 조회를 확인합니다. |
| 관리자에 보완 전 내용 표시 | **서버 기록 새로고침**을 누릅니다. 보완본이 실제 전송됐는지 차량에서 먼저 확인합니다. 필터/확인 필요 보기 때문에 안 보이면 **필터 초기화 → 전체 기록**으로 확인합니다. |
| 관리자 조회 실패 | 이전 조회값과 마지막 성공 시각·새 조회 실패 안내를 보여 줍니다. ‘기록0건’이라고 설명하지 않습니다. 연결 복구 후 새로고침합니다. |
| 음성 실패·빈 결과·사용 불가 | 직접 용도/메모를 선택하거나 **미확정으로 보관**합니다. 다른 음성 서비스로 대체하거나 결과를 자동 저장하지 않습니다. |
| 주행 중 음성·입력 취소 | 주차 후 운행 마치기부터 다시 확인합니다. 이전 음성 결과로 저장됐다고 주장하지 않습니다. |
| 저장 실패 | 초안/요약을 유지한 채 오류를 설명합니다. 저장 가능한 상태를 확인한 뒤 다시 저장합니다. 성공 화면을 강제로 띄우거나 기존 내용을 지우지 않습니다. |
| 버전 충돌·원인 확인 오류 | 해당 변경/후속 전송을 보류하고 개발 담당자에게 원인을 확인합니다. 새 이벤트·버전 추정·강제 덮어쓰기·초기화로 우회하지 않습니다. |
| 다른 탭 잠금 | 이번 시연 컨텍스트의 불필요한 탭만 닫고 한 탭을 사용합니다. 다른 사용자 창을 종료하지 않습니다. |
| 포트 충돌·처음부터 반복 | 이번 데모만 종료한 뒤 새 격리 서버/주소와 새 브라우저 컨텍스트로 시작합니다. 개발 DB/브라우저 저장소는 유지합니다. |

## 질문 대응용 설명

**기존 GPS 운행일지 서비스와 무엇이 다른가요?**  
“이번에 보여 드리는 핵심은 운행 직후 차량 화면에서 용도를 확인하고, 회사가 수신 기록과 보완 대상을 이어서 보는 흐름입니다. 차량 신호를 활용하는 제품을 목표로 하지만 지금 입력은 모의입니다. 기존 서비스별 기능이나 GPS 성능을 비교 검증하지 않았으므로 더 정확하거나 우월하다고 말씀드리지는 않습니다.”

**통신이 끊기면 어떻게 되나요?**  
“기록과 전송 대기열을 이 기기에 함께 보관합니다. 연결이 돌아오면 직접 전송하고, 서버 확인을 받은 뒤 완료로 바꿉니다. 같은 이벤트 재시도로 중복을 막는 흐름을 검증했습니다. 이 프로토타입만으로 영구 보관이나 모든 장애의 복구를 보장하는 것은 아닙니다.”

**사용자가 용도를 나중에 수정하면 어떻게 되나요?**  
“현재 화면에서는 주차 중 미확정 기록의 용도를 보완합니다. 같은 운행의 새 버전으로 보내므로 운행 건수가 늘지 않습니다. 원본 시각·거리·품질은 유지합니다. 모든 확정 기록을 자유롭게 수정하거나 관리자 승인을 받는 업무는 별도 범위입니다.”

**실제 차량·음성 SDK는 어디까지 연결됐나요?**  
“Android 앱과 공식 Vehicle SDK를 포함한 진단 APK의 빌드·자동 테스트까지 확인했습니다. Android 화면 실행과 Pleos 서비스 연결·실제 값 수신·음성·실차는 아직 검증하지 못했습니다. 오늘 보신 차량 상태와 음성은 웹 모의 입력입니다.”

**세무신고까지 실제로 가능한가요?**  
“현재는 수신 운행 기록을 조회하고 확인할 대상을 구분하는 단계입니다. 관리자 승인·기간 마감·실제 세무신고와 결과 수신은 구현하지 않았습니다. 이 집계를 세법상 적격성 검증이나 신고 완료로 설명하지 않습니다.”
