# Fleetlog MVP 1 · QR 차량 연결

현재 전체 MVP의 보완·월별 자료·CSV·모의 접수·GitHub 준비 결과는 [최종 인수인계](MVP_FINAL_HANDOFF.md)를 기준으로 합니다. 이 문서의 과거 테스트 수치는 해당 단계의 실행 이력입니다.
최신 차량 화면 변경: [MVP 차량 UI 업데이트](MVP_VEHICLE_UI_UPDATE.md). 주차 중에는 차량 화면을 표시하고 주행 중에만 비웁니다. QR과 대체 코드는 같은 발급 건이며 기본 유효기간은 10분입니다. 아래 검증 수치는 1단계 당시의 실행 이력입니다.

검증일: **2026-11-15 KST**. 가상 회사·직원·차량을 사용하지만 QR 발급→직원 선택→명시적 연결→SQLite 저장→차량/모바일/관리자 반영은 실제 로컬 HTTP로 동작합니다. 실제 로그인·운전자 인증·Pleos·Android·실제 음성·자동 운행 수집·세무신고는 이번 범위가 아닙니다.

## 구현과 화면 역할

| 경로 | 역할 |
|---|---|
| `/mvp/car?vehicleId=mvp-vehicle-001` | 주차 중 연결 안내·실제 SVG QR·대체 코드. 연결 후 주차 대기/운행 화면, 주행 중 빈 main. 해제 후 새 QR/코드 |
| `/mvp/driver?token=…` | 데모 직원 선택, 회사/부서/직책, QR 대상 차량 확인, 명시적 연결·해제. QR 먼저 열어도 원래 token URL을 유지 |
| `/mvp/admin` | 가상 회사·직원·차량과 차량별 직원/연결 시각. 버튼 없이 약1초 자동 조회. 실패와 실제 미연결 구분 |
| `/mvp/control?vehicleId=…` | 차량 선택, 세 역할 링크, 현재 QR URL/만료, 같은 PC에서 QR 역할 재현, 실제 연결 직원/시각. 차량 화면과 분리 |

단정한 네이비·청록 스타일과 기존 브랜드/카드/버튼 스타일을 재사용했습니다. 모바일390×844·360×720에서 가로 넘침과56px 조작 영역을 확인했습니다. 차량 화면은 최신 첨부 디자인의 밝은 회색·네이비·파랑을 사용합니다. 주행 중에만 콘텐츠를 비우며, 연결 성공 팝업은 표시하지 않습니다.

## 시작·주소·종료

프로젝트 루트에서 이미 설치된 Node24·의존성을 사용합니다.

```sh
npm run demo:mvp
```

웹 빌드 후 빈 포트를 OS에서 할당하고 **매번 새 임시 `mvp.sqlite`**를 만듭니다. 터미널의 `차량 화면`, `모바일웹 (PC 역할)`, `회사 관리자`, `시연 패널` 주소를 그대로 복사하세요. 고정 주소를 추정하지 않습니다. 먼저 시연 패널을 열면 편리합니다. 예시 포트가 필요하면 `npm run demo:mvp -- --port=4321`처럼 지정합니다. 포트 충돌이면 실패하며 기존 프로세스를 종료하지 않습니다.

이번 실제 명령 실행은 `http://127.0.0.1:62823/mvp/…`를 출력했습니다. 이는 이미 종료한 **이번 검증 이력**이며 다음 실행의 주소가 아닙니다. 기본 `HOST`, `PORT`, `FLEETLOG_DB_PATH`를 상속해 기존 개발 서버/DB를 선택하지 않습니다.

시연은 새 독립 브라우저 컨텍스트/시크릿 세션에서 시작합니다. 같은 PC에서 시연 패널의 ‘차량 화면 열기’, ‘운전자 모바일웹 열기’, ‘관리자 화면 열기’, ‘이 PC에서 QR 연결 재현’을 사용합니다. 세 화면은 동시에 열어도 운행 작성 Web Lock을 획득하지 않습니다.

화면을 닫거나 새로고침해도 **서버가 살아 있는 동안** SQLite 연결 상태를 다시 조회합니다. 직원 선택 선호만 새 키 `chagok.mvp.demoEmployeeId`에 저장해 같은 브라우저의 새 QR 탭으로 이어갑니다. 이것은 실제 인증 세션이나 연결 상태가 아닙니다. 이미 열린 다른 탭의 선택을 강제로 바꾸지는 않습니다. 브라우저가 달라지면 다시 계정을 선택합니다.

종료는 실행한 터미널의 **Ctrl+C**입니다. 이번 listener·직접 만든 임시 폴더만 정리하며 데이터는 **일회성**입니다. 서버 종료가 브라우저 저장소를 지우는 것은 아닙니다. 새 시연은 새 서버·새 독립 브라우저로 시작합니다. 기존 개발 DB·저장소·Android 데이터를 초기화하는 기능은 없습니다. 정상 종료 시 새 요청 수락을 중단하고 idle 연결을 정리하며, 최대1초 유예 뒤 남은 **이 서버의** 연결만 닫습니다. 강제 전원 종료/SIGKILL의 폴더 정리는 보장하지 않습니다.

## 가상 데이터

회사: `mvp-company-001` / **가상 Fleetlog 주식회사**.

| 직원 ID | 가상 이름 | 부서 | 직책 |
|---|---|---|---|
| `mvp-employee-001` | 가상 김차곡 | 가상 영업팀 | 가상 매니저 |
| `mvp-employee-002` | 가상 이연결 | 가상 운영팀 | 가상 대리 |

| 차량 ID | 표시 이름 | 가상 차량번호 |
|---|---|---|
| `mvp-vehicle-001` | 가상 업무 차량1 | 가상00가1001 |
| `mvp-vehicle-002` | 가상 업무 차량2 | 가상00가1002 |

모두 위 회사 소속입니다. 연결 정보는 `id`, `companyId`, `employeeId`, `vehicleId`, `connectedAt`, `disconnectedAt`, `status`를 저장합니다. 상태는 `active`/`disconnected`이며 active 연결을 각 차량 DTO의 `connection`에 제공하고 이력은 별도 배열로 유지합니다. 연결되지 않은 차량은 실제 성공 조회에서만 `connection:null`입니다.

## 연결·해제 시연

1. 시연 패널에서 차량1을 선택해 차량·관리자 화면을 엽니다. 모바일 화면에서 먼저 데모 직원을 선택하거나, QR 링크를 먼저 열고 직원을 선택합니다.
2. 기본 PC 시연은 ‘이 PC에서 QR 연결 재현’을 엽니다. QR URL에는 개인 정보 대신 서버 발급 token만 있습니다. **링크를 여는 것만으로는 연결이 생기지 않습니다.**
3. 직원의 회사/부서/직책과 차량명/가상 번호를 확인한 뒤 **이 차량에 연결**을 누릅니다.
4. 모바일의 서버 연결 확인, 관리자의 같은 직원·차량·시각, 차량 화면의 주차 대기·실제 직원·출발 전 거리 없음 상태를 확인합니다. 대체 연결 코드를 입력해도 같은 연결 절차를 사용합니다. 화면별 성공 플래그를 따로 만들지 않습니다.
5. 모바일의 **연결 해제**를 누릅니다. 관리자는 미연결로, 차량은 새 QR로 자동 바뀝니다.
6. 새 QR로 직원2를 선택해 연결합니다. 오래된 QR·연결 ID의 요청은 새 연결을 바꾸지 않습니다. 같은 직원이 다른 차량을 사용하려면 현재 연결을 먼저 해제합니다.

오류가 나면 서버/네트워크·실제 출력 주소를 확인합니다. 자동 조회 실패는 이전 값/마지막 확인과 함께 표시하고 연결 버튼을 비활성화합니다. 차량의 미연결 QR은 조회 실패 시 숨깁니다. 차량 조회 실패 시 주차 상태를 확인 필요로 표시하고 연결/운행 조작을 숨깁니다. 미연결이나 주차 성공으로 조용히 바꾸지 않습니다. 만료/잘못된 링크는 새 QR을 열고, 이미 사용 중인 차량은 원래 직원이 해제한 뒤 새 QR을 사용합니다. 저장 실패는 오류 응답이며 연결이 성공한 것처럼 표시하지 않습니다.

## PC와 휴대폰 접속의 차이

**기본127.0.0.1 QR은 PC 자신만 가리킵니다.** 실제 휴대폰에서는 접근할 수 없습니다. UI에도 PC용 주소임을 표시합니다. 실제 휴대폰/카메라 스캔은 이번 환경에서 **미실행**이며, 독립 모바일 폭 브라우저 컨텍스트로 검증했습니다.

동일 신뢰 네트워크에서 사용할 PC의 사설 IPv4와 사용 가능한 포트를 사용자가 확인했다면, **이번 MVP 서버만** 명시적으로 바인딩할 수 있습니다. 아래 주소/포트는 실제 환경으로 바꾸는 예시입니다.

```sh
MVP_BIND_HOST=192.168.0.20 \
MVP_PUBLIC_BASE_URL=http://192.168.0.20:4321 \
npm run demo:mvp -- --port=4321
```

휴대폰이 같은 네트워크에서 그 주소에 접근할 수 있어야 합니다. 방화벽·라우팅·기기별 기본 카메라 동작은 별도 확인합니다. 바인딩은 loopback 또는 명시적 사설 IPv4만 허용하고 wildcard/public IP 바인딩·production 모드는 거부합니다. 기존4000/5173 서버의 제한은 수정하지 않았습니다. 더미 데이터/데모 계정 선택이며 실제 회사 인증을 대신하지 않습니다.

사용자가 이미 마련한 HTTPS reverse proxy가 있다면 loopback 바인딩을 유지하고 `MVP_PUBLIC_BASE_URL`을 그 **http(s) origin**으로 설정할 수도 있습니다. origin에는 사용자정보·경로·query·fragment를 허용하지 않습니다. `/mvp/`, `/mvp-api/`, `/assets/`를 해당 MVP listener로 전달하는 설정은 사용자가 별도로 준비해야 합니다. 설정 문자열의 유효성·QR URL 구성은 테스트했지만 실제 외부 접근·HTTPS 프록시·LAN 휴대폰은 미검증입니다. 자동 배포/터널 개설은 하지 않았습니다.

## 서버 계약·저장 규칙

MVP 전용 `/mvp-api/`이며 기존 `/api/trip-events` 등은 변경하지 않았습니다. 이 서버의 기존 운행 API 경로는404입니다.

| 요청 | 결과 |
|---|---|
| GET `/mvp-api/state` | 회사·직원·차량 현재 연결·연결 이력·서버 시각·모드/QR 기준 주소 |
| GET `/mvp-api/vehicles/:vehicleId/qr` | 미연결이면 현재 유효 QR(token/url/code/issuedAt/expiresAt/validForMs). 만료 후 QR·코드 함께 갱신. 연결 중이면 연결 정보 |
| GET `/mvp-api/qr/:token` | QR 대상/상태 확인. 연결 생성 없음 |
| GET `/mvp-api/codes/:code` | QR과 동일한 발급 건 조회. 연결 생성 없음 |
| POST `/mvp-api/connections` `{token,employeeId}` 또는 `{code,employeeId}` | 두 자격 중 하나만 허용. 원자적 연결 또는 동일 활성 연결 반환 |
| POST `/mvp-api/connections/:id/disconnect` `{employeeId}` | 해당 연결만 해제. 같은 종료 요청 재시도는 새 연결에 영향 없음 |

- 기본 TTL은 **서버 시각 기준10분(600,000ms)**입니다. `randomBytes(32)`의 예측하기 어려운 token을 URL-safe 문자열로 발급하고 SQLite에는 SHA256 hash를 저장합니다. 원문은 표시를 위한 프로세스 메모리에만 보관합니다. 암호학적 token이 실제 직원 인증을 구현했다는 뜻은 아닙니다.
- 대체 코드는 혼동 문자를 제외한 무작위 6문자(표시 `ABC-DEF`)이며 hash만 저장합니다. QR과 같은 token row를 참조하므로 함께 만료·소비·폐기됩니다. 같은 활성 직원의 재시도만 원래 연결을 반환하며 해제 후에는 QR/코드를 함께 다시 발급합니다.
- token/차량/직원/회사 소속을 실제 저장소에서 검증합니다. 회사 ID를 클라이언트가 임의 지정할 수 없습니다. JSON은 필요한 필드만 허용하고4KiB로 제한합니다. 잘못된JSON/직원400, 잘못된token404, 만료/폐기410, 사용 중/다른 직원 재사용409, 소속/직원 불일치403을 구분합니다.
- `BEGIN IMMEDIATE` 안에서 token 소비와 연결 생성을 함께 commit합니다. 차량과 직원 각각의 active 연결에 unique index를 두어 동시에 두 직원이 연결되거나 한 직원이 여러 차량을 조용히 바꾸지 못합니다.
- 같은 사용 token·같은 직원의 **아직 활성인** 요청 재시도는 TTL이 지나도 원래 연결 ID를 반환합니다. 새 연결을 만드는 예외가 아닙니다. 다른 직원은409이며 해제 뒤에는 누구라도 이전 token으로 재연결할 수 없습니다.
- 해제/QR 갱신의 차량 generation과 정확한 연결 ID로 이전 QR·늦은 연결/해제 요청을 차단합니다. 토큰을 바꿔 기존 연결을 자동 덮어쓰지 않습니다.
- 쓰기 실패 시 트랜잭션을 rollback해 token만 소비되거나 반쪽 연결이 남지 않습니다. DB는 기존 운행과 별도 `mvp_*` 테이블뿐입니다. 과거 운행을 새 직원에게 소급 연결하지 않습니다.
- 화면은 약1초 순차 polling과 실제 서버 재조회 결과만 사용합니다. 요청 취소/세대 검사로 이전 조회가 최신 화면을 덮지 않으며, 직원 선택 변경은 진행 중 클라이언트 작업의 결과 적용을 취소합니다. 클라이언트 취소가 이미 서버에서 확정된 작업을 되돌렸다는 뜻은 아닙니다. 실제 상태는 다음 조회에서 확인합니다.
- Host/Origin은 실제 listener 또는 명시적 QR public origin만 허용합니다. 캐시는 no-store·referrer는 no-referrer입니다. 실제 로그인/세션/회사 권한/보안 인증은 없으므로 운영 배포로 사용하지 않습니다.

QR은 [qrcode-generator](https://github.com/kazuhikoarase/qrcode-generator)2.0.4로 실제 URL을 인코딩하고4모듈 여백을 가진 SVG로 표시합니다. URL을 SVG 마크업으로 삽입하지 않습니다. 검증용 [jsQR](https://github.com/cozmo/jsQR)1.4.0은 개발 의존성으로만 추가했습니다. 표시된 SVG를 실제 브라우저 canvas로 래스터화한 뒤 독립 decoder로 URL이 정확히 같은지 검증했습니다. 장식 이미지나 성공 응답 대체가 아닙니다.

## 1단계 당시 파일과 실행 검증 (이력)

주요 파일은 `services/mvp/{server,store}.mjs`, `scripts/demo-mvp.mjs`, `apps/web/src/mvp/{MvpApp.tsx,mvp.css,qr.mjs,qr.d.mts}`, `main.tsx` 경로 분기, 신규 backend/launcher 테스트와 `e2e/mvp.spec.mjs`입니다. package/lock에는 작은 QR 관련 의존성과 새 명령만 추가했습니다. 기존 `npm run dev`·`npm run demo` 명령/실행 코드는 유지했습니다.

처음 전체 E2E는21통과·3실패였습니다. 하나는 자동 polling 화면을 닫는 서버 종료 대기였으며 **새 MVP 서버의 bounded shutdown과 실제 미완성 POST/keepalive 종료 회귀**를 추가했습니다. 나머지2개는 기존 화면 크기 검사가 비동기 writer lock 이후의 UI 생성 전에 DOM을 측정하던 race로, 렌더 완료를 기다린 뒤 같은 가로 넘침/영역/버튼 높이 조건을 검사하도록 보완했습니다. 초기 신규 E2E locator/Host fixture 오류도 실제 DOM/HTTP에 맞게 수정했으며 성공 조건을 낮추지 않았습니다. 최종 전체 실행 결과와 보존 비교는 아래에 기록합니다.

저장 공간은 시작 약610MB에서 도중 약54MB로 급감해 작은 jsQR 설치도 global npm cache 경로에서 ENOSPC로 **실행 실패**했습니다. 사용자 파일/SDK/AVD/기존 캐시를 지우지 않았습니다. 공간 재관측 후 이번 작업 전용 npm cache를 사용해 설치를 **실행 통과**했고 소스·테스트를 계속했습니다. 두 라이브러리의 npm unpacked metadata 합은 약835KB이며 SDK/새 브라우저/대용량 도구 설치는 없습니다. 실패 로그·최종 로그·가상 데이터 화면은 ignore 대상 `test-results/mvp-step1/`에 보관합니다.

### 기존 데이터·프로세스 보존과 결과 자료

작업 시작 시 소스 manifest127개는 일치했고 기존 변경을 되돌리지 않았습니다. 실제 개발 DB `services/api/data/fleetlog.sqlite`를 `mode=ro`·`PRAGMA query_only=ON`으로 읽어 기준을 남겼고 마지막에 전체 행을 다시 비교했습니다. **운행4건·영수증6건의 ID·server/local revision·payload·원본/보완값·ACK·모든 저장 시각이 동일**합니다. 과거 보고의 숫자에 맞춘 것이 아니라 이번 실제 조회 결과입니다. 자료는 `test-results/mvp-step1/before/database.json`, `after/database.json`입니다.

기존 API PID49059/4000·Vite PID49060/5173은 유지했습니다. 실제 `npm run demo:mvp`는 이번 별도62823 listener와 새 임시 폴더만 사용했고 Ctrl+C 뒤 둘 다 정리된 것을 확인했습니다. E2E/단위 테스트의 임시 DB·서버는 finally/test cleanup으로 정리했습니다. 기존 브라우저 저장소·Android 데이터는 열어서 초기화하지 않았습니다. 테스트용 기존 키 sentinel도 세 화면 사용 전후 원문 그대로임을 확인했습니다. 최종 디스크 여유는 관측 시점 **591,773,696B**이며 변동분 전체를 프로젝트 원인으로 단정하지 않습니다.

최종 `npm run check` 근거는 `test-results/mvp-step1/check-final.log`, 이미 빌드된 현재 웹에 `npx playwright test --trace off`로 실행한24개 근거는 `e2e-final.log`입니다. 처음21통과/3실패는 `e2e-first.log`, `e2e-first-results.json`에 별도로 보존했습니다. 표준 재현은 `npm run check` 후 `npm run test:e2e`이고 신규만 확인하려면 `npx playwright test e2e/mvp.spec.mjs --trace off`입니다. 대용량 trace/녹화를 추가하지 않았습니다.

가상 데이터만 담긴 `car-qr.png`, `driver-connected.png`, `admin-connected.png`3장(합계약136KB)을 저장해 직접 확인했습니다. 연결 후 빈 차량은 DOM 자식/텍스트/폼/카드/팝업0 assertion으로 검증했습니다. 실제 CLI 화면의 connection ID/회사/직원/차량 일치와 해제 결과는 `cli-run.json`에 있습니다. 물리 휴대폰 스캔·LAN 접근과 실제 인증을 확인한 자료는 아닙니다.

## 다음 음성 대화·자동 기록 작업에 넘길 정보

연결된 세 화면은 서버의 `connection.id/companyId/employeeId/vehicleId/connectedAt/status`를 공유합니다. 다음 작업은 이 **서버의 활성 연결**을 식별 기준으로 사용할 수 있습니다. 이후 기록 저장 시 활성 여부·회사 권한·기록 구간과 해제 경계를 서버에서 다시 검증해야 하며 클라이언트 선호 계정이나 지난 연결을 그대로 신뢰하면 안 됩니다.

QR 연결 자체는 운행 수집 시작·운전자 실명 인증·주차 확인·마이크 권한·신고 동의가 아닙니다. 음성 결과는 확인 가능한 초안을 거쳐야 하고 자동 수집은 별도의 검증된 상태/SDK와 정책이 필요합니다. 기존 명시적 수집 시작·주행 중 편집 차단·원본/Outbox/ACK 규칙과 연결하는 작업은 후속입니다. 기존 운행의 source/직원/회사 바인딩을 소급 변경하지 않습니다.
