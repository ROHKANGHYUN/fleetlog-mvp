## 데이터와 표시 기준

### 목록과 기간

- 기본 정렬은 **운행 시작 시각 내림차순**, 동시각은 tripId 오름차순입니다. 오래된 시작순 전환과 **10건 단위 페이지 이동**을 제공합니다.
- 같은 tripId는 높은 serverVersion, 같은 버전이면 높은 localRevision의 수신본 하나를 선택합니다. 서버도 최신 한 행만 제공하지만 화면에서도 방어적으로 중복 제거합니다. 변경 이력을 추정하지 않습니다.
- 시작·종료·서버 반영·조회 시각은 연도를 포함한 `YYYY.MM.DD HH:mm:ss KST`로 표시합니다. 운영체제/브라우저의 현지 시간대와 무관합니다.
- 기간은 **운행 시작 시각** 기준입니다. 시작일 00:00 KST 이상, 종료일 다음 날 00:00 KST 미만입니다. 예를 들어 한국 날짜 2026-11-15는 UTC `2026-11-14T15:00:00.000Z` 이상, `2026-11-15T15:00:00.000Z` 미만입니다.
- 자정을 넘는 운행을 나누거나 거리를 재계산하지 않습니다. 잘못된 날짜·역전된 범위는 별도 입력 오류로 표시하고 목록·집계 표시를 보류합니다.

### 필터와 범위

기간·용도·용도 미확정 여부·거리 품질·차량·이용자·검색은 AND 조건입니다. 검색은 차량 ID·이용자 ID·메모 중 하나에 대소문자 구분 없이 포함되는지 검사합니다. 차량·이용자 선택지는 실제 전체 수신 데이터에서 구성합니다.

필터 변경·초기화·정렬·보기 전환 시 페이지를 1로 바꾸고 상세 선택을 해제합니다. 새 수신본으로 페이지 수가 줄면 유효한 페이지로 보정합니다. 상단 요약·전체 목록·용도별 요약은 같은 필터 범위이며, ‘확인 필요’는 그 범위에서 확인 사유가 있는 운행만 표시합니다. 페이지를 바꿔도 집계 범위는 줄어들지 않습니다.

### 상태와 확인 필요

각 행은 **서버 수신**, **용도 입력됨/미확정**, **유효 거리/거리 확인 필요**를 독립적으로 표시합니다. 차량에만 저장한 미전송 기록은 관리자 데이터에 없습니다. 용도 입력이 관리자 승인·기간 마감·세무신고 완료를 뜻하지 않습니다.

확인 필요 사유는 `purpose=null`, 또는 품질이 gap이거나 누적거리 값이 불명확/역전된 경우입니다. 한 운행에 사유가 두 개면 각각 표시하되 목록·전체 확인 필요 수는 운행 한 건으로 셉니다. 용도 사유 수와 거리 사유 수는 겹칠 수 있음을 표시합니다. purpose를 보완해도 원본 gap을 유지합니다. 보완 요청 발송 기능은 없습니다.

### 거리와 용도별 요약

품질 valid이고 두 누적거리 값이 유효한 비음수이며 종료가 시작 이상인 기록만 차분을 합산합니다. 합계 내부 단위는 정수 m, 화면은 km이며 소수 최대 세 자리로 표시합니다. 이는 기존 mock 계약의 단위입니다.

- 필터 범위 수신 운행 수, 일반 업무·출퇴근·개인 용도·미확정별 수를 표시합니다.
- gap 등 거리 확인 필요 기록을 0km로 바꾸지 않습니다. 합산 가능한 기록 수와 제외 수를 함께 표시합니다.
- 유효 기록이 없으면 ‘집계 가능 거리 없음’, 해당 용도 기록이 없으면 ‘수신 기록 없음’, 유효 거리의 실제 합계가 0m면 ‘0 km’를 표시합니다.
- 용도가 미확정이어도 거리 품질이 valid이면 미확정 그룹의 거리 합계에 포함합니다. 이것은 수신본 집계이며 전체 기간의 누락·세무 적격성 검증은 아닙니다.

### 상세

운행 ID, 차량·이용자, 원본 시작·종료 시각, 누적거리와 차분, 품질을 ‘거리·시각 원본’으로 표시합니다. 운전자 용도·메모, 서버 시각·버전·리비전·mock 출처를 별도로 표시합니다. gap의 숫자 차분은 ‘참고값, 유효 거리 합계에서 제외’로 표시합니다.

선택은 tripId만 보유하고 상세 내용은 매 렌더링의 최신 현재 페이지 행에서 다시 찾습니다. 새 수신본은 열린 상세에도 반영되며 필터·페이지에서 벗어난 대상은 닫습니다. 원본 수정·전체 변경 이력·승인·기간 마감·세무신고는 구현하지 않았습니다.

## 조회와 오류

- 최초 조회 중에는 숫자 0건이나 성공한 빈 목록을 표시하지 않습니다. 최초 실패는 연결 오류이며 데이터 없음과 구분합니다.
- 정상 수신이 빈 배열이면 ‘아직 서버가 수신한 운행이 없습니다’, 필터 결과만 비면 ‘필터에 맞는 기록이 없습니다’로 표시합니다.
- 재조회 중·재조회 실패는 이전 성공 데이터와 마지막 성공 조회 시각을 유지합니다. 실패 사실을 화면 상단에서 안내합니다. 정상 완료는 별도 성공 안내로 표시합니다.
- 재조회마다 이전 요청을 abort하며 증가하는 요청 번호도 확인합니다. transport가 abort를 무시해도 오래된 성공/실패가 최신 화면을 덮어쓰지 않습니다. 새로고침 버튼의 연속 조작도 같은 규칙을 사용합니다.
- 전체 수신 snapshot만 새로 조회하므로 필터 변경 자체는 서버 요청을 만들지 않습니다. 응답 도착 때 현재 필터를 다시 적용합니다.
- 응답 모양이나 필수 필드가 잘못되면 조회 오류로 처리하고 이전 값을 유지합니다. 잘못된 응답을 빈 목록으로 바꾸지 않습니다.

## 실행과 남은 수동 확인

본 앱은 기존 `npm run dev` / `http://127.0.0.1:5173`의 ‘Fleetlog 비즈’ 탭입니다. 이미 실행 중인 서버를 다시 띄우거나 종료할 필요는 없습니다.

실제 개발 DB를 건드리지 않는 후속 브라우저 검증은 다음처럼 **새 임시 DB와 별도 포트**로 실행합니다. 4304 포트가 사용 중이면 다른 빈 로컬 포트를 선택하세요. 기존 프로세스를 종료하지 않습니다.

```sh
npm run build
FLEETLOG_DB_PATH="$(mktemp -d)/fleetlog.sqlite" PORT=4304 npm start
```

새 시크릿 창/새 브라우저 컨텍스트에서 `http://127.0.0.1:4304`만 사용하세요. 기존 4000/5173 탭과 저장소를 재사용하지 않습니다. 테스트를 끝낸 뒤 위 터미널의 Ctrl+C로 **이번에 시작한 서버만** 종료합니다. 다음 순서로 확인합니다.

1. 기록 시작→주행→주차→마치기→음성 안내 완료→중간/최종 결과 전달→초안 수정→요약→저장. 로컬 저장만으로 관리자에 나타나지 않는지 확인한 뒤 온라인 전송하고 목록·상세를 조회합니다.
2. 미확정 보관·전송 후 확인 필요에 한 건 표시, 차량에서 용도 보완·재전송 후 같은 tripId의 높은 버전과 단일 건수를 확인합니다. gap은 별도로 중단/재실행을 이용한 격리 테스트에서 확인합니다.
3. 음성 취소·재출발·다른 탭/앱 비활성화 후 결과 미반영, 오프라인 저장→실제 ACK 후 관리자 반영을 확인합니다.
4. 한국 날짜 경계·용도·미확정·거리·차량·이용자·검색과 요약을 대조하고 필터 변경 시 페이지/상세가 해제되는지 확인합니다.
5. 최초 빈 수신·필터 빈 결과·연결 실패·기존 조회 후 실패·연속 새로고침을 확인합니다. 조회 실패를 재현하려고 기존 개발 서버를 종료하지 않습니다.

별도 메모리 fixture인 개발 서버 `/qa/`에서는 본 데이터와 분리해 전송·조회 실패를 주입할 수 있습니다. 관리자에서 먼저 조회한 뒤 상단 ‘전송·조회 실패 모의’를 켜고 다시 새로고침하면 이전 데이터·마지막 성공 시각·실패 안내를 확인할 수 있습니다. 이 fixture는 실제 SQLite가 아닌 모의 서버 Map을 사용하므로 실 HTTP 검증과 구분합니다.

## 5단계 예외·동기화 검증 인수인계

1. 브라우저 제어 복구 후 위 실제 클릭·크기 검증을 완료하고, 열린 상세의 재조회 갱신·필터/페이지 이동·긴 메모·많은 수신 기록을 확인합니다.
2. ACK 유실·오프라인·저장 공간 부족·서버 409·선행/후행 리비전·재실행·단일 writer를 차량/관리자 경계에서 반복 검증합니다. 중복 eventId 우회와 원본 덮어쓰기는 허용하지 않습니다.
3. 현재 필터·집계는 전체 수신 목록을 받아 계산합니다. 큰 데이터에서는 서버 페이지/필터 계약과 snapshot 일관성·집계 API를 별도로 설계해야 합니다. 이번에는 서버 계약을 확장하지 않았습니다.
4. 실제 인증·회사 권한·감사 이력·충돌 해결·보완 요청 발송·승인·마감·세무신고는 여전히 미구현입니다. 서버 수신과 혼동하지 않습니다.
5. 실제 Pleos SDK 연결과 권한·단위·수명주기는 별도 공식 문서/대상 환경 확인 후 진행합니다. 웹 mock과 Android 차량 앱은 계속 별도 클라이언트입니다.
