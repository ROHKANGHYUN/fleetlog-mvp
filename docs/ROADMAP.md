# 개발 범위와 다음 단계

## 1단계 현재 상태 · 2026-11-15

웹 개발 서버·45개 테스트·빌드·실제 브라우저의 확정/미확정/보완·gap/잠금 흐름을 확인했습니다. Android 누락 소스는 복구했으나 빌드 도중 디스크 공간 부족으로 실패했고 SDK35·AVD도 준비되지 않았습니다. 다음 작업은 디스크 여유 확보와 Android mock 빌드·실행 검증부터 시작합니다. 상세 증거와 미검증 범위는 [VALIDATION.md](VALIDATION.md), Android 재현 명령은 [Android 검증 기록](../apps/car-android/VALIDATION.md)을 따릅니다.

## 이번 ZIP의 완료 기준

명시적 시작 → mock 주행 → 주차 → 목적 확인 또는 보류 → 로컬 보관 → API 수신 → 관리자 조회가 연결되는 개발 기반. 웹은 목적 보완 리비전·Outbox 재시도·충돌 보류를 포함한다. Android는 별도 mock scaffold이며 기능 차이와 빌드 한계는 해당 README를 기준으로 한다.

## 우선순위

| 순위 | 작업 | 완료를 판단할 증거 |
|---|---|---|
| P0 | Android 빌드·AVD | JDK17/SDK35 환경의 테스트 로그, APK, 에뮬레이터 동작 |
| P0 | 실제 SDK 가능 범위 검증 | 공식 SDK 버전·차량 속성·권한·단위·UX 제한 확인표 |
| P0 | 네이티브 동등성 | 미확정→보완 리비전, 동일 이벤트 재시도, 앱 종료/재실행 테스트 |
| P1 | 실제 음성 adapter | 권한 거부·취소·결과 지연·주행 전환에서 초안 오저장 없음 |
| P1 | UX 게이트 | parked 판단·불명확 상태·주행 제한 정책의 실기기 검증 |
| P1 | 실험 데이터 확보 | 기록 완료 시간·미확정률·보완 시간의 사전/사후 비교 |
| P2 | 인증·회사 권한 | 서로 다른 회사의 읽기·쓰기 격리 테스트 |
| P2 | 관리자 승인·기간 마감 | 누락/중복/역전 거리 검증과 마감 후 수정 정책 |
| P3 | 세무 전달 | 세무 전문가 검토를 거친 내보내기부터 도입 |

자동 신고·신고 결과 수신은 외부 서비스 계약과 권한·책임 확인 후 별도 범위로 결정한다. 현재 앱이 세법상 적격 기록임을 보장하지 않는다.

## 실제 SDK 연결 전에 확인할 사항

- 공개 문서와 팀에 제공된 SDK 버전이 일치하는가?
- 누적거리·기어/주행 상태·UX 제한 신호에 실제 접근할 수 있는가?
- 각 값의 단위·초깃값·미수신·오류·갱신 주기를 어떻게 해석하는가?
- 앱 종료·백그라운드·전원 전환 시 수집 보장 범위는 어디까지인가?
- 운전자와 법인 차량을 어떻게 바인딩하고 권한을 철회하는가?

확인되지 않은 항목은 mock으로 표시한다. unavailable을 0이나 parked로 변환하지 않는다.
