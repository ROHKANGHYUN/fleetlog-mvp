# MVP 차량 화면·운행 흐름 업데이트

현재 전체 MVP의 보완·월별 자료·CSV·모의 접수·GitHub 준비 결과는 [최종 인수인계](MVP_FINAL_HANDOFF.md)를 기준으로 합니다. 이 문서의 과거 테스트 수치는 해당 단계의 실행 이력입니다.
검증일: **2026-11-15 KST**. 가상 직원·차량과 모의 거리·발화를 사용하는 격리 웹 MVP입니다. 차량·모바일·관리자는 같은 서버 상태를 조회하고, 전송은 실제 로컬 HTTP와 SQLite 영수증을 사용합니다.

## 변경한 화면과 이전 규칙의 대체

최신 사용자 요구로 다음 세 규칙을 대체했습니다. 과거 테스트의 항상 빈 차량/출발 전 질문/도착 즉시 확정 조건도 새 동작 검증으로 변경했고, QR 소유권·원본·ACK·중복·오류·기존 Web Lock 검증은 유지했습니다.

| 이전 | 현재 |
|---|---|
| 연결 후 항상 빈 차량 | 주차 중 연결/운행 화면, **주행 중에만 콘텐츠와 조작을 비움** |
| 연결·출발 전 목적 질문 | 주차 관측 후 **운행 마치기**에서 질문 시작 |
| 모의 도착 즉시 저장·전송 | 도착은 관측만. 고정 후보의 음성 동의 또는 미확정 보관에서 자동 저장·전송 |

`VehicleScreen.tsx`·`vehicle.css`의 실제 HTML/CSS로 첨부 이미지의 밝은 회색 배경, 네이비 글자, 흰 카드, 회청색 테두리, 파란 주 버튼과 좌우 배치를 구현했습니다. 배경 이미지나 정적 거리/이름을 사용하지 않습니다. 차량 헤더는 **Fleetlog 운행기록**입니다. 후속 서비스 이름 통일에 따라 모바일·관리자 표시도 **Fleetlog / Fleetlog 비즈**를 사용합니다. 작은 **MVP · 모의 차량** 표시는 주차 화면에 계속 보입니다.

1920×1080의 외곽 48px을 1280×720에서는 32px, 960×540에서는 24px로 조정합니다. 버튼 높이는 최소 56px이며 공식 차량 UX 인증 기준을 뜻하지 않습니다. 더 작은 세로 창은 한 열로 바뀝니다. 기존 MVP의 flex 중앙 정렬/padding 규칙이 새 grid에 섞이던 문제를 화면 범위별 스타일로 분리했습니다.

## 상태별 화면과 버튼

| 실제 서버 상태 | 차량 화면과 허용 행동 |
|---|---|
| 미연결·모의 주차 확인 | 실제 QR/코드, 서버 연결/거리 제공 상태. **연결 완료·다시 확인**은 GET 재조회만 수행 |
| 연결 직후·출발 전 | 실제 가상 운전자/차량·수집 대기. 거리 `—`, 출발 전 안내, 운행 마치기 비활성. 운행/질문 생성 없음 |
| `driving` | 자식 요소·텍스트·폼·버튼·팝업 없는 빈 main |
| `parked`·관측 운행 | 관측 거리·원래 시작 시각·직원, 품질·해당 차량 전송 대기 건수. 운행 마치기/계속 운행/기록 종료 |
| 목적 질문/재확인 | 같은 좌우 카드 유지, 오른쪽 안내만 단계에 맞게 변경. 발화/실패/동의 조작은 시연 패널에만 있음 |
| `unknown` 또는 조회 실패 | 주차 확인 배지·종료/연결 조작을 제공하지 않음. QR/네트워크 성공 표시 숨김, 상세 진단은 패널에서 확인 |
| 세션 중지 | 연결은 유지, **기록 시작**으로 명시적 재개. 새로고침·동일 QR 요청 재시도로 재개하지 않음 |

거리/시각/직원/대기 건수는 서버의 현재 운행과 해당 차량 큐에서 계산합니다. 23.4km는 모의 provider의 한 주행 구간 23,400m에서 나온 값입니다. 실제 계기판/SDK 측정값이 아닙니다. provider 미수신·유효하지 않은 값은 0 또는 정상 거리로 대체하지 않습니다. 품질 불완전이면 **거리 확인 필요**이며 목적 확인으로 정상 품질이 되지 않습니다.

**계속 운행**은 후보·대화·초안을 취소하고 기존 tripId·시작 시각·시작 누적거리·관측값을 유지합니다. 버튼 자체는 출발 신호가 아니므로 주차 상태로 남고, 다음 모의 출발에서 같은 구간을 이어갑니다.

**기록 종료**는 직원 연결 해제와 별개입니다. 양의 이동이 관측된 미완료 구간은 **마지막 관측 시각·누적거리**로 목적 null 기록과 이벤트를 함께 저장합니다. 종료 버튼 시각까지 미관측 시간을 늘리지 않습니다. 빈/미관측 운행 이벤트는 생성하지 않습니다. 불완전 품질은 유지하고 세션은 false로 보관합니다. 주차 상태에서 기록 시작을 눌러야 다시 수집 대기가 됩니다.

## QR·대체 코드·10분

- 기본 유효기간은 **서버 시각 기준 600,000ms**이며 화면에도 **10분간 유효 · 한 번만 사용**을 표시합니다. QR 응답의 `issuedAt`·`expiresAt`·`validForMs`에서 같은 기준을 사용합니다. 테스트용 짧은 TTL을 주입한 경우에도 실제 주입값을 표시합니다.
- QR은 기존 32바이트 무작위 token을 담은 실제 URL입니다. 대체 코드는 무작위 6문자를 `ABC-DEF` 형태로 표시하며 고정 샘플을 사용하지 않습니다. 대소문자/구분 공백은 정규화합니다. QR에는 기존 4모듈 quiet zone이 유지됩니다.
- `mvp_pairing_codes`에는 코드 hash와 같은 `mvp_qr_tokens` row 참조만 저장합니다. QR/코드의 만료·세대·회사·직원·활성 연결 검증과 소비는 같은 로직·트랜잭션을 사용합니다.
- 한쪽으로 확정되면 다른 방식도 함께 소비됩니다. 같은 활성 직원의 동일 발급 건 재시도는 원래 연결 ID만 반환합니다. 다른 직원은 409, 해제 후 이전 QR/코드는 410이며 새 발급 건을 사용합니다. 경쟁 요청은 한 건만 성공합니다. 조회만으로 연결하지 않습니다.
- 모바일 `/mvp/driver`에서 코드 입력→코드 확인→데모 직원 선택/차량 확인→이 차량에 연결 순서입니다. 코드/QR을 먼저 열어도 URL을 유지하여 계정 선택 후 이어갑니다. 차량 화면에 입력 키보드는 없습니다.
- 가상 계정 선택은 실제 인증이 아닙니다. 짧은 코드를 운영용 보안 인증으로 사용하지 않습니다.

새 경로는 GET `/mvp-api/codes/:code`, 연결 POST의 `{code,employeeId}` 대체 입력뿐입니다. `{token,employeeId}`는 유지하고 두 자격을 함께 보내는 요청은 400으로 거부합니다. 기존 `/api/trip-events`, 개발 DB 스키마·운행 데이터·localStorage 키·Android 계약은 변경하지 않았습니다.

## 운행·음성·자동 저장·수신

```text
명시적 QR/코드 연결 → 모의 주차·수집 대기 (운행·질문 없음)
  → 모의 출발 → driving/빈 차량 → 모의 도착 → parked/관측 카드
  → 운행 마치기 → candidateEnd 고정 → 질문 안내 완료
  → 모의 발화 초안 → 재확인 안내 완료 → 모의 네
     또는 나중에·무응답·실패·지원하지 않는 발화 → 목적 미확정
  → 같은 트랜잭션으로 종료 원본 + 준비된 이벤트 보관
  → 패널 uploader의 실제 HTTP → 수신 운행 + receipt commit
  → 실제 수신본만 모바일/관리자에 반영
```

질문은 “어디를 다녀오셨고, 어떤 목적으로 운행하셨나요?”입니다. 기존 정해진 모의 발화 예시는 호환 유지합니다. 목적지를 모르는 표현에는 내용을 만들지 않습니다. 최종 초안은 확인 안내 후 **모의 네**에서만 확인 목적이 되며, 별도 저장/전송 버튼은 없습니다. **아니요**는 같은 후보를 유지한 새 질문이고 이전 동의는 적용하지 않습니다.

`candidateEnd`는 운행 마치기 요청의 시각과 마지막 유효 누적거리로 한 번 고정합니다. 질문/초안 수정/재시도 중에도 늘어나지 않습니다. 목적 입력 중 모의 재출발은 같은 tripId로 이어가고 초안·후보·prompt를 취소합니다. 연결/운행/대화/prompt/claim/명령 ID와 현재 단계가 맞지 않는 늦은 결과는 409로 거부합니다. 제어 요청도 tripId·conversationId snapshot을 보내며, ‘운행 없음’ snapshot의 늦은 종료 요청이 새 운행을 끝내지 못합니다.

모의 차량 상태/세션은 새 `mvp_vehicle_runtime` 테이블에 보관합니다. 서버가 실행 중인 동안 화면 새로고침으로 복원합니다. 일반 개발 화면의 FleetController나 writer lock을 MVP에서 새로 만들지 않습니다. 기존 운행 화면의 writer lock은 유지합니다.

저장 실패 시 종료 원본·큐가 함께 rollback되고 후보·초안을 보존합니다. 전송은 이전 MVP uploader/준비 본문/ACK/영수증 규칙을 유지합니다. 같은 이벤트 재시도는 같은 문자열을 쓰며, 서버 수신·영수증을 원자적으로 저장합니다. 관리자 수신 목록은 localStorage나 업로드 요청 자체를 성공 근거로 사용하지 않습니다. 오래된 직원의 큐도 원래 직원·차량에 귀속됩니다.

**MVP의 수집 대기와 수신은 같은 격리 SQLite 안의 별도 테이블**입니다. 장치 로컬 오프라인 저장소나 실차 자동 수집이 아닙니다. 업로드 차단은 운행 수신 요청만 막고 QR·상태·제어 통신은 계속합니다. 실제 자동 전송을 위해 시연 패널을 열어 두세요. 일시 오류는 같은 이벤트로 제한 재시도하며 409/계약 오류는 보류합니다. 상세 상한과 복구 규칙은 [MVP2 전송 규칙](MVP_STEP2_VOICE_TRIP.md#전송ack재시도)에 있습니다.

## 실행과 시연

설치된 Node 24·의존성·Chrome을 사용하며 새 도구/SDK를 설치하지 않았습니다.

```sh
npm run demo:mvp
```

매 실행마다 **새 임시 DB와 빈 포트**를 사용합니다. 터미널에 실제 출력된 차량·모바일·관리자·시연 패널 주소를 독립 브라우저에서 엽니다. 고정 포트를 추정하지 마세요. 종료는 해당 터미널 Ctrl+C이며 이번 실행의 listener·임시 폴더만 정리합니다.

1. 시연 패널에서 차량1을 선택하고 차량/관리자를 엽니다. PC 연결 링크로 QR을 재현하거나 모바일 화면에서 차량의 실제 코드를 입력합니다. 가상 직원을 선택해 연결을 확정합니다.
2. 차량이 주차 대기·가상 김차곡을 표시하고 운행 마치기는 비활성인지 확인합니다. 패널의 시연 음성 준비는 선택 사항입니다.
3. 패널 **모의 출발**에서 차량이 비워지고, **모의 도착**에서 23.4km 주차 카드가 표시됩니다. 아직 수신/대기 운행은 없습니다.
4. 차량 **운행 마치기**→패널의 안내 완료 모의→모의 발화 전달→재확인 안내 완료 모의→모의 네. 실제 TTS가 준비됐으면 브라우저 완료 이벤트 뒤 다음 모의 답변을 전달할 수도 있습니다.
5. 관리자 수신 목록의 동일 tripId 한 건, 목적·실제 수신 상태·거리 합계를 확인합니다. 직접 소리를 듣지 않았다면 음성 출력 검증이라고 설명하지 않습니다.
6. 다음 운행에서는 업로드 차단 후 도착·마치기·모의 나중에를 누릅니다. 해당 차량 전송 대기 1건, 관리자 수신 건수 유지, 미확정 기록 보존을 확인합니다. 패널 새로고침 후 업로드 복구 시 같은 ID가 한 번만 수신되는지 봅니다.
7. 계속 운행은 같은 구간·주차 상태를 유지합니다. 기록 종료 후 새로고침하면 기록 시작을 요구하며 연결 해제와 다릅니다.

기본 `127.0.0.1` QR은 PC용입니다. 물리 휴대폰용 명시적 사설 IP/QR 기준 주소 설정과 보안 범위는 [MVP QR 접속 안내](MVP_STEP1_QR.md#pc와-휴대폰-접속의-차이)를 따릅니다. 자동 외부 배포·터널·기존 서버 제한 해제는 없습니다.

## 데이터 보존과 남은 범위

작업 전 실제 소스 manifest **147개**가 일치했고 시작 당시 사용자 변경은 없었습니다. 기존 개발 DB를 `mode=ro`·`PRAGMA query_only=ON`으로 열어 운행 **4건**·영수증 **6건**의 **전체 행**을 기준으로 남겼습니다. 작업 후 읽기 전용으로 다시 전체 행을 비교하여 **모든 열의 값이 동일**함을 확인했습니다. ID·리비전·payload·ACK·저장 시각을 포함하며 건수만 비교한 것이 아닙니다. 근거는 `before/database.json`·`after/database.json`·`preservation.json`입니다. 기존 API PID49059/4000·Vite PID49060/5173을 유지했고 두 서버 HTTP200을 확인했습니다. 이번 CLI PID31939/49324만 SIGINT로 종료한 뒤 포트 닫힘·직접 만든 임시 폴더 삭제·종료 코드0을 확인했습니다. 과거 보고의 숫자에 맞춘 것이 아닙니다.

시작 여유 공간은 **1,626,451,968B**, 최종 보존 확인 시 **528,506,880B**였습니다. 새로운 의존성·SDK·브라우저를 설치하지 않았고 사용자 파일/캐시를 삭제하지 않았습니다. 시스템 여유 공간 변동 전체를 프로젝트 탓으로 단정하지 않습니다.

기존 `npm run dev`·`npm run demo`·`npm run demo:mvp` 정의/실행 스크립트, 기존 domain/운행 계약/API/Android/저장소 키는 유지했습니다. 테스트는 새 임시 DB·별도 포트·독립 브라우저를 사용합니다. 기존 DB/브라우저/Android 초기화·사용자 프로세스 종료·캐시 삭제는 하지 않습니다.

실제 인증·회사 권한·일반 자연어 이해·실제 음성인식·SDK·Android 실행·실차 데이터·운영 배포·세무신고는 미구현 또는 미검증 범위입니다. SDK 옵션 APK 빌드는 이번 웹 시연의 실차 연결 근거가 아닙니다. 다음 실차 단계는 권한·서비스·단위·UX 제한·장치 수명주기를 별도로 확인해야 합니다.

최종 소스 manifest는 **152개**입니다. 기존147개 중 이번 범위14개를 수정하고 새5개를 추가했습니다. package/lock·실행 스크립트·기존 domain/API/Android 파일은 시작 hash와 동일합니다.

주요 파일: `services/mvp/{store,server,workflow}.mjs`, `apps/web/src/mvp/{VehicleScreen.tsx,vehicle.css,MvpApp.tsx,mvp.css,workflow-types.ts,RuntimeControl.tsx}`, `tests/{mvp-code,mvp-workflow}.test.mjs`, `e2e/{mvp,mvp-voice-trip,mvp-vehicle-ui}.spec.mjs`.
