# Fleetlog · 법인차 운행기록 MVP

차량에서 남긴 짧은 기록을 회사의 관리 업무까지 연결하는 **로컬 mock 프로토타입**입니다. 서비스는 **Fleetlog**, 관리자 화면은 **Fleetlog 비즈**입니다.

QR 연결 → 모의 운행 → 주차 후 용도 확인/미확정 보관 → 실제 로컬 HTTP 수신 → 모바일 용도 보완 → 회사 월별 집계 → 자료 생성·CSV 다운로드 → 모의 접수 결과까지 연결됩니다. 실제 인증·차량 SDK·세무신고 서비스는 아닙니다.

## 빠른 시작

필요 환경은 **Node.js 24.x와 npm**, 일반 웹 브라우저입니다. 웹 시연에는 JDK·Android SDK가 필요하지 않습니다. 새로 받은 소스라면 프로젝트 루트에서 의존성을 설치합니다. 이미 설치했다면 다시 설치하지 않아도 됩니다.

```sh
npm ci
npm run demo:mvp
```

웹 타입 검사·빌드 후 **새 임시 SQLite와 사용 가능한 로컬 포트**를 만들고 다음 주소를 터미널에 출력합니다. 고정 포트를 추정하지 말고 실제 출력된 링크를 사용하세요.

| 화면 | 출력 주소의 경로 | 역할 |
|---|---|---|
| 시연 패널 | `/mvp/control` | 차량 선택, 화면 열기, 모의 출발·도착·발화, 업로드 차단/복구, 월말 처리·모의 실패 재현 |
| 차량 | `/mvp/car` | 주차 중 QR/코드 또는 운행 카드, 주행 중 빈 화면 |
| 운전자 모바일웹 | `/mvp/driver` | 데모 직원 선택·연결·해제, 본인 미확정 수신 기록 보완 |
| 관리자 | `/mvp/admin` | 연결 현황, 필터·상세·확인 필요, 월별 집계·자료·모의 접수 |

먼저 **새 시크릿 창/독립 브라우저 환경**에서 시연 패널을 열고 화면 링크를 사용하세요. 직원 선택은 실제 로그인이 아닙니다. 같은 서버가 실행 중이면 새로고침 후 연결·기록·자료·접수 결과를 다시 조회합니다. 자동 전송을 위해 **시연 패널을 열어 둡니다**.

종료는 실행한 터미널에서 **Ctrl+C**입니다. 이번 데모 서버와 직접 만든 임시 폴더만 정리하며 데이터는 일회성입니다. 반복 시연은 같은 명령으로 새 서버·새 독립 브라우저를 시작합니다. 기존 개발 DB·브라우저 저장소·Android 데이터를 지우는 초기화는 없습니다. 포트를 명시해야 한다면 `npm run demo:mvp -- --port=4321`처럼 사용하며 충돌하는 서버를 종료하지 않습니다.

기본 `127.0.0.1` QR은 **같은 PC용**입니다. 휴대폰은 동일 네트워크와 명시적 접속 주소가 필요합니다. [QR 접속 설정](docs/MVP_STEP1_QR.md#pc와-휴대폰-접속의-차이)을 참고하세요. 자동 외부 배포·터널은 없습니다.

## 전체 시연 순서

가상 회사 1개·직원 2명·차량 2대를 사용합니다. 기존 개발 운행을 가져오지 않습니다.

1. 패널의 PC QR 링크 또는 차량의 **실제 연결 코드**를 모바일웹에서 엽니다. 데모 직원 선택 후 차량을 확인하고 **이 차량에 연결**합니다. QR/코드는 같은 발급 건으로 10분 후 함께 만료됩니다.
2. 패널에서 **모의 출발**을 누르면 차량 화면이 비워집니다. **모의 도착**에서 주차 카드가 표시되며, 이때는 아직 저장·전송하지 않습니다.
3. 차량의 **운행 마치기**를 누릅니다. 종료 후보 시각·거리가 고정됩니다. 패널에서 **모의 나중에**를 누르면 미확정 보관·자동 전송됩니다. 목적을 확인하려면 안내 완료 → 모의 발화 → 재확인 안내 완료 → 모의 네 순서입니다.
4. 관리자와 모바일의 **서버 수신 완료**를 확인합니다. 모바일의 해당 기록에서 **용도 보완 → 용도/목적지/상세 목적 → 보완 내용 확인 → 확인하고 보완 저장**을 누릅니다. 관리자에 자동 반영되며 최초 운행·ACK는 바뀌지 않습니다.
5. 관리자 **월별 자료·모의 세무처리**에서 운행 시작 시각의 한국 날짜 기준 월을 선택합니다. 회사 전체·전체 차량 범위이며 위 운행 목록 필터와 독립적입니다.
6. **월별 자료 생성** 후 같은 버전의 **운행 내역 CSV / 가상 차량 비용 CSV**를 실제 다운로드합니다. 고정 가상 비용은 2026-11에 3건·80,200원, 2026-10에 1건·55,000원이며 다른 월에 복제되지 않습니다.
7. 준비 조건이 충족되면 **모의 제출**합니다. 서버 처리 후 **모의 접수 완료·DEMO 접수번호**가 표시되고 새로고침 후 유지됩니다. 실제 신고가 아닙니다.

추가로 패널에서 **운행 업로드 차단** 후 기록을 만들면 수신 전 큐에 남습니다. **운행 업로드 복구**에서 같은 이벤트가 중복 없이 수신됩니다. 보고서 생성 후 해당 월 기록을 추가/보완하면 기존 자료는 **갱신 필요**, 새 생성은 새 버전입니다. 패널 **모의 제출 실패 재현**으로 만든 접수 실패는 **모의 제출 성공으로 복구 → 관리자 모의 제출 재시도**로 새 시도를 남깁니다.

TTS가 재생되지 않으면 텍스트를 확인한 뒤 **안내 완료 모의**를 사용하세요. 실제 청취·마이크·음성인식 성공을 뜻하지 않습니다. **계속 운행**은 같은 구간을 유지하고 출발을 강제하지 않으며, **기록 종료**는 연결을 유지한 채 수집 세션을 중지합니다. 다시 기록하려면 주차 중 **기록 시작**이 필요합니다.

## 실제 처리와 모의 처리

| 구분 | 범위 |
|---|---|
| 실제 로컬 동작 | 화면 간 서버 상태 공유, QR/코드 발급·검증, HTTP·SQLite, 보완 이력, 스냅샷·CSV 파일, 모의 접수 상태 영속 저장 |
| 모의 입력/결과 | 직원 계정, 차량 상태·거리, 발화 내용, 가상 비용, DEMO 접수 결과 |
| 음성 합성 | 지원 브라우저의 TTS 요청과 완료 이벤트. 실제 소리 청취·STT와 별도 |
| 미포함 | 운영 인증·회사 권한·승인/마감·Pleos/실차·실제 STT·카드/회계·홈택스·실제 신고/납부·운영 배포 |

MVP 수집 대기와 수신은 **같은 격리 SQLite의 서로 다른 테이블**입니다. 차량 장치 오프라인 저장소가 아닙니다. 업로드 차단 중에도 QR·조회·제어 통신은 유지됩니다. 기존 개발 웹의 localStorage/Outbox와는 별도 구현이며, 웹 시뮬레이터와 Android 앱도 별도 클라이언트입니다.

## 테스트

```sh
npm run check
# 위에서 빌드한 현재 웹으로 Chrome 전체 회귀
npx --no-install playwright test --trace off
```

`check`는 Node 테스트 → TypeScript → Vite 빌드입니다. `npm run test:e2e`는 빌드를 포함하는 기존 통합 명령입니다. 브라우저 테스트는 각자의 임시 DB·포트·독립 컨텍스트를 사용하고 기존 개발 서버를 종료하지 않습니다.

설치된 macOS Chrome을 자동 사용합니다. 다른 기존 브라우저 실행 파일은 `CHAGOK_BROWSER_PATH=브라우저실행파일경로`로 지정할 수 있습니다. 브라우저가 없다면 별도 준비가 필요합니다. 테스트 로그·캡처·CSV·임시 DB는 공유 소스에 포함하지 않습니다.

이번 최종 실행 결과와 재현·보존·GitHub 준비 상태는 [최종 인수인계](docs/MVP_FINAL_HANDOFF.md)에 있습니다. 이전 232개/36개 결과와 구분합니다.

## 기존 개발 화면과 Android

```sh
npm run dev
# 기존 격리 3장면 웹 시연
npm run demo
```

`dev`는 기존 웹 `http://127.0.0.1:5173`·API `http://127.0.0.1:4000`을 사용하며 개발 DB는 `services/api/data/fleetlog.sqlite`입니다. 이미 실행 중이면 같은 서버를 사용하세요. MVP 데이터를 섞지 않습니다. `demo`는 이전 차량·관리자 운행 프로토타입을 새 임시 환경에서 실행합니다. [이전 3장면 대본](docs/STEP7_DEMO_PLAN.md)을 참고하세요. `npm start`도 로컬 개발 API이므로 `dev`와 같은 포트에서 동시에 시작하지 않습니다.

Android 코드는 보존했고 이번 최종 MVP 작업에서는 수정·실행하지 않습니다. [Android README](apps/car-android/README.md), [런타임 미검증 범위](docs/STEP6_RUNTIME.md)를 참고하세요. APK 빌드 이력은 Android 화면·Pleos 서비스·실차 실행 성공을 뜻하지 않습니다.

## 저장소와 공유

| 경로 | 역할 |
|---|---|
| `apps/web/src/mvp` | 이번 MVP 웹 화면·브라우저 음성/전송 port |
| `services/mvp` | 격리 연결·수집·수신·보완·월별 자료·모의 접수 |
| `scripts/demo-mvp.mjs` | 새 임시 DB·포트·종료 정리 |
| `packages/domain`, `packages/contracts`, `services/api` | 기존 개발 운행·Outbox·API 계약 |
| `apps/car-android` | 별도 Android mock·선택적 SDK 진단 소스 |
| `tests`, `e2e`, `docs` | 자동 검증·실제 브라우저 시나리오·완료 기록 |

소스·`package.json`·`package-lock.json`·필수 설정·문서만 공유합니다. `.env`/비밀값·DB/WAL/SHM·node_modules·dist·SDK/캐시·APK·로그·실행 결과는 제외합니다. 기본 실행은 `.env.example`을 복사하지 않아도 되며 예시에는 가상 로컬 값만 있습니다. `source:mock`, 패키지명·API 경로·저장소 키는 이름 변경 때문에 바꾸지 않습니다.

이번에는 Git 초기화·스테이징·커밋·원격 생성/변경·push를 하지 않습니다. GitHub 업로드의 준비 상태와 다음 결정 항목은 [최종 인수인계](docs/MVP_FINAL_HANDOFF.md#github-공유-준비)를 확인하세요.
